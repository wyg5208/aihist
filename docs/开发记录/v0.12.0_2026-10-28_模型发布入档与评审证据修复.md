## 2. 任务目标

v0.11.0 修好了两条排除理由的实现，并上线生产、跑起第一轮回补。本轮要回答的是**回补之后为什么还是什么都进不来**：`150` 条送审，`admitted=2`，`excluded=148`。

用户的原始诉求（v0.11.0 那一条）里有一半还没兑现：

> 我看到比如 DeepSeek-v4.1-Flash-1017 这种大模型有突破性表现的也可以纳入。时间窗的话我认为可以放开，因为需要补充过往几年中的所有可用记录。

时间窗已经放开（`MAX_AGE_DAYS = 0`，理由码只作为词表保留）。剩下的是「模型发布能不能入档」：`DeepSeek V4.1 Flash 1017` 这类条目现在**不再被规则丢弃**，却卡在评审面板手里。

## 3. 问题诊断

### 3.1 第一轮回补的漏斗

生产 `sync_runs`（`2026-10-28 09:38:49`，`backfill`）：

```
raw=1380  created=2  merged=40  reviewed=150  admitted=2  excluded=148  held=0  panel=1  ms=215871
notes: catalog:26; ledger:pending:1380; panel:5/5; review_admitted:2; review_excluded:148;
       cap:events; ledger:verdicts:2501
```

`events` 159 → 161。淘汰率 **148/150** 不是「门槛变严」能解释的形状：规则门已经把新闻型的都筛掉了，进面板的都是规则分 ≥ 35 的候选，其中一半是模型目录里的真实发布。

### 3.2 面板到底看到了什么

取回 150 条里的模型类票型（`review_decisions`）：

| 候选 | 中位分 | include 票 | 评委给的 flags |
| --- | --- | --- | --- |
| Gemma 4 26B A4B | 68 | 0/5 | `auto-aggregated`、`catalog-auto`、`aggregator_only` |
| Qwen3.8 2.4T A95B | 58 | 0/5 | `aggregator_only`、`insufficient_evidence` |
| Nemotron 3 Ultra | 50 | 0/5 | `single-source`、`aggregator_only` |
| Claude Opus 4.8 | 45 | 0/5 | `auto-aggregated`、`insufficient_evidence` |
| MiniMax M3.1 Flash | 42 | 0/5 | `aggregator_only`、`insufficient_evidence` |
| **DeepSeek V4.1 Flash 1017** | **42** | **0/5** | `auto-aggregated`、`catalog-auto`、`single-source` |

五席独立给出的理由是同一个：「仅目录参数，未见架构或能力突破」。五个不同厂商的模型同时误判同一条，问题不在评委，在**证据**。

### 3.3 根因一：摘要把模型卡扔了

`parse_openrouter` 是把 `description` 读下来的：

```python
"description": model.get("description") if isinstance(model.get("description"), str) else "",
```

但 `openrouter_candidates` 没用它，改用模板：

```
DeepSeek V4.1 Flash 1017 由 DeepSeek 提供，开放权重，上下文窗口 262K token。
条目由 OpenRouter 模型目录自动汇总。
```

`auto-aggregated` 这个 flag 就是这么来的——摘要自己说了它是自动汇总的。更糟的是**模板恰好丢掉了唯一能区分「新模型」与「新档位」的信息**。直连 OpenRouter `/api/v1/models`（464 个模型）核对原文：

| 模型 | 模型卡原文（节选） |
| --- | --- |
| DeepSeek V4.1 Flash 1017 | `sparse mixture-of-experts …`（`the October 17, 2026 snapshot of DeepSeek V4.1 Flash`） |
| Gemma 4 26B A4B | `only 3.8B activate per token — near-31B quality` |
| Nemotron 3 Ultra | `55B active of 550B, hybrid Transformer-Mamba MoE` |
| GPT-6.1 Terra Pro | `the same underlying model as GPT-6.1 Terra` |

模型卡里既有架构与激活参数（该入档），也有「同一底座的 Pro 模式」与「某日快照」（该淘汰）。模板把两者一起抹平成「上下文窗口 262K」，面板只能判「证据不足」。

### 3.4 根因二：`has_tier_variant` 把本代旗舰压出面板

第一版修复只解决了证据，规则门的第二处缺陷随之显形。用真实数据跑规则门（`985 raw → 288 clusters → 241 个模型类别候选`）：

```
进面板 217   被挡 24
  20  同族包装变体（has_tier_variant）
   4  规则分 < 35
```

被挡名单里是 `Gemini 3.8 Flash`、`Qwen3.8 Max (0902)`、`Step 3.7 Flash`、`GPT-5.3-Codex` 这类**本代旗舰**。原因是档位后缀扣 8 分，而模型目录通常只列一个档位——`Gemini 3.8` 在目录里只有 `Flash`，它就成了「和自己的档位名重复」的那一条，`score = 33` 低于 `RULE_PANEL_THRESHOLD = 35`，连送审机会都没有。档位的语义是「可能是既有模型的包装」，不是「这个模型不重要」。

### 3.5 泛滥风险评估

放开档位扣分后，模型发布会不会变成发布日志？统计当前模型目录：**240 条候选 / 217 个家族**；197 个家族只有 1 条，20 个有 2–3 条，**没有家族达到 4 条**。每轮面板上限 24 条，模型发布最多占一半。不构成泛滥。

## 4. 修复方案

### 4.1 摘要改用厂商模型卡（双实现）

`ingest/normalize.py`：

```python
MAX_CARD_CHARS = 180          # 卡片截断长度；面板展示 260 字符，机械事实要活过这层截断
_WS_RUN = compile_ascii(r"\s+")

def card_text_of(value): ...       # 折成一行，按词边界截断并补「…」
def model_card_summary(card, *, headline, facts):
    """模型卡原文在前，机械事实（开放权重/上下文/模态）在括号里。"""
```

OpenRouter 摘要变成：

```
sparse mixture-of-experts …（DeepSeek V4.1 Flash 1017 由 DeepSeek 提供，开放权重，上下文窗口 262K token）
```

无卡时回退到原来的事实模板（`summaryKind: "template"`），有卡时 `summaryKind: "card"`，界面标签「厂商模型卡」。Hugging Face 侧的摘要也删掉了「条目由 Hugging Face 模型库自动汇总。」——同一句废话让 `hf-*` 的候选拿到同一个 `auto-aggregated` flag。

### 4.2 档位扣分减半（双实现）

```python
score += -4 if has_tier_variant(candidate) else 6      # 原 -8 / +6
```

-4 让 `Gemini 3.8 Flash` 从 33 分回到 37 分，越过面板门槛，由模型卡回答「这是不是新模型」。原始语义保留：同族档位仍然扣分。

### 4.3 `RUBRIC_VERSION` → `chronicle-v4`

`pipeline` 只在 `cached_row.rubric_version == RUBRIC_VERSION` 时复用旧票型。两处改动都改变了「旧票型当初是在对什么做判断」，不升版本，那 148 条按模板摘要判出的「仅目录条目」淘汰会永远匹配上、永远不再送审。这条机制比改动本身更容易被漏掉，因此写进了 `rules.py` 的注释与 `README`。

### 4.4 效果验证（真实 API + 真实评委）

用 `.env` 里的五席密钥做不改代码的对照实验：同一批 10 条候选，模板摘要 vs 模型卡原文。

| 候选 | 模板摘要 | 模型卡 |
| --- | --- | --- |
| Qwen3.8 2.4T A95B | 58 / 0 票 | **76 / 3 票 include** |
| Nemotron 3 Ultra | 50 / 0 票 | **78 / 3 票 include** |
| Gemma 4 26B A4B | 68 / 0 票 | 62 / 1 票 |
| GPT-6.1 Terra Pro | 45 / 0 票 | **25**（卡里写「同一底座」） |
| DeepSeek V4.1 Flash 1017 | 40 / 0 票 | **35**（卡里写「10 月 17 日快照」） |

方向是自洽的：真发布从中位 50 上下抬到 76–78 并凑够 3 票，而「Pro 模式变体」与「日期快照」被模型卡自己的措辞压到更低。**要让用户点名的那条 `DeepSeek V4.1 Flash 1017` 入档，靠的不是降门槛，而是它在卡里确实写着是快照——该淘汰；同代真发布 `Qwen3.8 2.4T`、`Nemotron 3 Ultra` 才应该进。**

## 10. 总结

这一轮的核心不是「标准太严」，而是**证据没送到评委面前**：模型目录的候选被摘要成「上下文窗口 + 自动汇总」，五席各自判为「仅目录条目」，五票一致地错。修法是把厂商模型卡原文交出去——卡片既能证明架构突破，也能自证「同一底座」和「某日快照」，判据因此重新站在事实一边。

顺带修掉的是同一件事的另一半：`has_tier_variant` 的 -8 分让「本代只有 Flash 一个档位」的旗舰被自己的档位名扣到面板门外。扣分保留、幅度减半，判「是不是新模型」的权力交回模型卡。

两处改动都必须让旧票型失效，否则 148 条「仅目录条目」会因 `rubric_version` 匹配被无限复用——`RUBRIC_VERSION` 升到 `chronicle-v4` 不是形式主义，而是这次修复能否生效的开关。
