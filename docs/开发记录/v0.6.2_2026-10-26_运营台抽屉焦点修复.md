## 二、任务目标

用户在 `https://aihist.net/admin#/partners` 新建合作方时反馈：名称、跳转代号、目标地址等输入框**每次只能输入一个字母**，必须反复点击输入框才能继续输入。

本次目标：

1. 让抽屉内的受控输入框在一次点击后可以连续输入，不再被焦点管理打断；
2. 保留抽屉原有的无障碍契约——打开时焦点进入面板、`Escape` 关闭、关闭后焦点归还触发元素；
3. 在共用组件上修一次，覆盖所有复用该抽屉的运营台页面，而不是逐页打补丁。

## 三、问题诊断

| 现象 | 原因 |
| --- | --- |
| 输入一个字符后光标消失，必须再点一次输入框 | `Drawer` 的焦点管理 `useEffect` 依赖 `[open, onClose]`。表单输入触发 `setState` → 页面重渲染 → 调用处传入的内联箭头 `onClose` 引用变化 → effect 先执行 cleanup（`restoreTo.current.focus()`，把焦点还给打开抽屉前的按钮），再执行 effect 体（`panel.current?.focus()`，把焦点抓到面板 `div`）。两次聚焦都发生在输入框之外，输入框因此失焦 |
| `#/partners`、`#/users`、`#/keys`、`#/applications` 等页面同时复现 | 这些页面调用 `Drawer` 时一律传内联箭头，例如 `onClose={() => setEditing(null)}`、`onClose={() => setComposeOpen(false)}`、`onClose={() => setPanel(null)}`。每次渲染都是新函数，依赖比较必然不等 |
| 选择框、按钮没有同样症状，只有文本框明显 | 受控文本输入每敲一个字符就 `setState` 一次，effect 每字符重跑一次；下拉选择一次交互只改一次状态，按钮通常直接关闭抽屉，所以症状被掩盖 |
| `#/applications` 的处置弹窗也会被抢焦点 | 抽屉不因弹窗打开而卸载，`panel !== null` 仍为真。在叠开的 `ConfirmDialog` 里输入配额或理由会让 `Applications` 重渲染，抽屉的旧 effect 照样重跑，把焦点从弹窗输入框抢回抽屉面板 |
| 关闭抽屉后焦点有时不回到最初那个按钮 | effect 每次重跑都会把 `restoreTo.current` 覆写成「cleanup 聚焦后的当前元素」。第一次重跑之后，记录下来的已不是真正的触发按钮，而是被 cleanup 聚焦的按钮或面板 |
| `Escape` 监听器随每次击键反复解绑/绑定 | 同一个 effect 同时负责键盘监听，`onClose` 变化导致整段副作用重建；功能上还能用，但属于无谓的监听器抖动 |

**结论**：不是输入框本身有限制（`TextInput` 没有 `maxLength`，`onChange` 也正常回传完整值），而是**焦点被一个依赖不稳定的 effect 在每次渲染后夺走**。把 `onClose` 从依赖中拿掉、同时保证 `Escape` 读到的仍是最新回调，是问题的正解。

## 四、方案与实施

**取舍一：在 `Drawer` 内部用 ref 持有最新 `onClose`，而不是要求调用方 `useCallback`。**

调用方传内联箭头是 React 里最常见、也最易读的写法；把「必须 memo 化回调」变成使用约束，等于把组件内部的缺陷转嫁给 7 个页面、8 处调用点。更糟的是这类约束**不会产生类型错误**，下一次有人新加一个抽屉就会静默复发。修复放在共用组件里，调用方一行不用改。

**取舍二：焦点 effect 的依赖只保留 `[open]`，`onClose` 通过 ref 读取。**

```tsx
const close = useRef(onClose);

useEffect(() => {
  close.current = onClose;
}, [onClose]);

useEffect(() => {
  if (!open) return;
  restoreTo.current = document.activeElement;
  const onKey = (event: KeyboardEvent) => {
    if (event.key === "Escape") close.current();
  };
  document.addEventListener("keydown", onKey);
  panel.current?.focus();
  return () => {
    document.removeEventListener("keydown", onKey);
    if (restoreTo.current instanceof HTMLElement) restoreTo.current.focus();
  };
}, [open]);
```

这样 effect 只在 `open` 翻转时建立/拆除一次：打开时记录触发元素并聚焦面板，关闭时移除监听并把焦点还回去，输入过程中的重渲染不再触碰焦点。

**被否决的方案**

| 方案 | 否决理由 |
| --- | --- |
| 给 8 处 `onClose` 包 `useCallback` | 改动面大、易漏、且无类型保护；共用组件之间的行为契约应该由组件自己保证 |
| 从依赖数组删掉 `onClose` 并加 `eslint-disable` | 键盘监听会永久闭包住首次渲染的 `onClose`。当前多数调用是无参的 `setX(null)`，暂时看不出问题，但一旦某个页面在关闭时需要读取最新状态，就会静默执行旧逻辑 |
| 移除 `panel.current?.focus()` | 抽屉打开后焦点留在背后的列表上，读屏用户不知道上下文已切换，`Escape` 也要求先点进抽屉才生效，破坏既有无障碍契约 |
| 改成给第一个输入框 `autoFocus` | 详情类抽屉（`#/content`、`#/runs`、`#/audit`）没有输入框；即便有，`autoFocus` 只在挂载时生效，无法替代「打开时把焦点放进面板」的语义，还会打乱读屏的阅读顺序 |
| 把输入框改成非受控 / 加 `key` 强制重挂 | 治标不治本：焦点仍会在 effect cleanup 中被抢走，且会改变表单的受控语义与校验方式 |

**变更点**

| 文件 | 变更 |
| --- | --- |
| `src/admin/components/Drawer.tsx` | 新增 `close` ref 与同步 effect；`Escape` 改调 `close.current()`；焦点管理 effect 依赖由 `[open, onClose]` 改为 `[open]`。共 +15 / −2（`git diff --stat`） |

**关键实现细节**

- `useRef(onClose)` 的初值就是首次渲染的回调，因此即使同步 effect 还没跑，第一次 `Escape` 也不会拿到 `undefined`；后续每次渲染由 `[onClose]` 的 effect 更新为最新值。
- cleanup 现在只在 `open` 变 `false` 或组件卸载时执行，`restoreTo.current` 保持为打开抽屉那一刻的 `document.activeElement`，焦点归还因此变准。
- 遮罩与「关闭」按钮仍然直接调用 props 上的 `onClose`，走的是本次渲染的最新函数，不受 ref 影响。
- 抽屉内叠开的 `ConfirmDialog` 不再被背后的抽屉抢焦点：`Applications` 的配额/理由输入重渲染时，抽屉 effect 不会重跑。
- 同一处修复对只读详情抽屉（`#/runs`、`#/audit`）没有行为副作用，只是不再每次重渲染重挂键盘监听。
