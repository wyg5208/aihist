## 二、任务目标

1. **统一档案起点**：页眉、页脚、侧栏时代分带三处对「档案从哪一年开始」给出同一个答案，并且这个答案来自数据而非文案。
2. **给公共站补深色**：默认跟随系统偏好，手动选择可持久化，首屏不能闪；`theme-color` 随主题变化。
3. **隔离运营台**：公共站深色不得改写运营台调色板；两边主题选择互不影响。
4. **静态引用页支持深色**：`/e/<slug>.html` 在深色系统下可读，同时不破坏「不含 JavaScript」的既有契约，打印时回到黑白。
5. **修两个既有缺陷**：窄屏整页横向溢出；侧栏未命中来源族的 9px 文字对比度不足。

## 三、问题诊断

### 1. 档案起点有三个数字

| 现象 | 原因 |
|---|---|
| 页眉写 `Vol. I · 1950—2026`，页脚写「从 1912 年的早期自动机」 | 页眉把 1950 写成字面量，页脚另写一个 1912；两处没有共同来源 |
| 选中 1912–1949 任意年份，侧栏「时代摘要」显示的是 1950 段的「学科诞生与两条路线」 | `ERAS` 最早一段的 `from` 是 1950，`eraFor()` 找不到更早的段就回退到末段；分带数据里根本没有 1912–1949 这一段 |
| 读者看到的起点与档案实际内容不一致 | 种子 158 条里有 9 条早于 1950，最早是 1912 年 Torres Quevedo 的国际象棋自动机；`docs/AI纪年_借鉴与实施计划_v1.0.md` 也早已写「最早 1912 年」 |

结论：不是文案笔误，是**三处各自维护一个年份**，而分带数据缺一段。只改页眉数字会让侧栏继续错标 1912–1949。

### 2. 公共站只有一套配色

| 现象 | 原因 |
|---|---|
| 系统处于深色模式时，公共站仍是纸白底，夜间阅读刺眼 | `globals.css` 只有一套 `:root` 令牌，没有 `prefers-color-scheme` 分支，也没有手动入口 |
| 运营台早在 v0.3.0 就有深/浅双主题，公共站没有 | 两套 bundle 独立演化，运营台的 `src/admin/theme.css` 只管运营台 |
| 移动端浏览器状态栏始终是米色 | `index.html` 的 `theme-color` 固定为 `#f6f2e9`，不随主题变化 |

### 3. 公共站深色令牌会穿透到运营台（本轮最危险的回归点）

| 现象 | 原因 |
|---|---|
| 公共站深色块一旦写成 `:root[data-theme="dark"]`，运营台的 `--paper` 会变成 `#14120f`（公共站深色纸色），而不是它自己的 `#0f1116` | 两条规则都挂在同一个 `<html>` 上。公共站深色块的特异度是 `(0,2,0)`，运营台 `src/admin/theme.css` 的别名块 `:root { --paper: var(--c-bg); }` 是 `(0,1,0)`；特异度高的声明胜出，**导入顺序救不了** |
| 改导入顺序、或把运营台 CSS 放最后，仍然会复发 | 平手时才看顺序；只要公共站选择器多一个属性，就再次压过运营台。CSS 拆分、按需加载、bundle 顺序变化都会让“当前恰好能跑”失效 |
| 症状不是整页变黑，而是运营台局部用 `--paper` 的地方变成暖棕黑，和 `--c-bg` 的冷蓝黑并排 | 运营台自己的 `body` 用 `var(--c-bg)`，共享组件用 `--paper` 别名；别名被覆盖后两套底色同时存在，像渲染 bug 而不是主题 |

### 4. 静态引用页的深色不是换个变量就行

| 现象 | 原因 |
|---|---|
| 深色下引用块出现一层灰雾 | `.cite` 的叠层写死 `rgba(255, 255, 255, 0.35)`，在近黑纸上是提亮而不是压暗 |
| 静态页读不到站点的手动主题选择 | `/e/<slug>.html` 按契约不含 JavaScript，无法读 `localStorage`；只能靠 CSS 媒体查询跟随系统 |
| 深色页面打印会白底白字 | 打印时浏览器通常不输出背景色，而文字仍是 `--ink` 的浅色；令牌不重置就会得到一张几乎空白的纸 |

### 5. 两个既有缺陷被这轮工作顺带暴露

| 现象 | 原因 |
|---|---|
| 819px 视口下整页可以横向滚动，`scrollWidth=1960` | `.scrubber` 是 `display:flex` + `overflow-x:auto`，50 个年份按钮都是 `flex:none`，min-content ≈1936px；`main` 作为栅格项默认 `min-width:auto`，把内容的 min-content 当成整列下限，溢出从 `main` 传到文档 |
| 侧栏「来源与校验」里未命中的来源族几乎看不清 | 9px 文字用 `var(--rule-strong)`（浅色 `#b9ae9b`）作前景，对纸色 `#f6f2e9` 的对比度只有 **1.96:1**，远低于 4.5:1；分隔线颜色被误用成了文字颜色 |

## 四、方案与实施

### 4.1 核心取舍

**只换令牌，不碰组件。** 公共站的颜色本来就走 CSS 变量，深色不需要一套平行样式，只需要在同一组令牌上换值。组件层零改动，意味着任何一个新组件只要用现有令牌就自动支持两套主题，也避免 `dark:` 前缀散落在 JSX 里。七个令牌无法由「换主色」推导出来——alpha 洗色叠在近黑纸上会消失，分布条在深色下会反成眩光——所以给它们单独命名；`--chart-4/5` 两个字面量图表色同理，在深色块里重新取值。

**首屏主题由 `index.html` 的内联脚本决定，React 只接管后续。** `useEffect` 在首次绘制之后才跑，深色用户会先看到一帧纸白；主题切换最不能容忍的就是闪一下。脚本必须在模块图之前执行，因此不能 `import` `theme.ts`，只能把 storage key 与两个 chrome 颜色抄一份。这是本轮唯一一处「故意的重复」，两份文件互相写了注释；下一步应当用门禁比对这几行字面量，而不是靠人记。

**运营台隔离用「表面标记」，不用特异度竞赛。** 公共站深色块必须挂在 `:root` 上，但运营台也把 `data-theme` 写在同一个 `<html>` 上，且它靠 `:root` 的别名接管旧变量名。三种写法里：提高运营台选择器（例如 `:root[data-theme]`）只能打成平手，依赖导入顺序；给公共站换一个类名会把 `data-theme` 的语义拆成两套；最终选的是最笨但最明确的一种——`admin.html` 的 `<html>` 写 `data-surface="admin"`，公共站深色块加 `:not([data-surface="admin"])`。它表达的是「这块表面不归公共站调色板管」，而不是「谁的选择器更长」。代价是这个属性必须留在 `admin.html`，删掉就会退回串色——两处都写了指向对方的注释。

**静态页只用 CSS，不引入启动脚本。** `check-pages.mjs` 断言每个引用页的 `<script>` 恰好一个、必须是 `type="application/ld+json" data-page-jsonld`，另有「不得加载外部脚本」；README 也明确写「静态页不含 JavaScript」。这不是风格偏好，而是让引用页在无 JS 环境、爬虫与阅读模式里稳定解析的契约。把启动脚本复制到 158 个页面技术上只要十几行，但会让上述断言失效，并给每个引用页增加一次阻塞式脚本执行，收益只是「手动选择能跨到静态页」。因此接受一个明确缺口：**静态页只跟随系统偏好，站点手动选择不生效**；在浅色系统上手动选了深色的读者，点进 `/e/...` 会回到浅色。要补这个缺口应单独设计（服务端按 Cookie 输出对应调色板，或有意识地放宽门禁并同步改 README 与检查器），不在主题迭代里顺手绕过。

**1912 是数据事实，不是页眉文案。** 只改 Masthead 的数字，侧栏仍会把 1912–1949 标成「学科诞生」。把起点提成 `ARCHIVE_START_YEAR`、并在 `ERAS` 末尾补一段之后，页眉、页脚、侧栏分带三处同源；段数从 14 变 15，`eraFor()` 的回退逻辑天然覆盖 1912 以前（当前没有更早条目）。

**溢出用 `min-w-0` 修，不用 `overflow-x: hidden` 盖。** 栅格项的 `min-width:auto` 会把 `.scrubber` 的 min-content 当成整列下限；给 `main` 与侧栏包裹层加 `min-w-0`，横向滚动交还给 `.scrubber` 自己的 `overflow-x:auto`。`overflow-x:hidden` 也能让 `scrollWidth` 变小，但会把侧栏的 sticky 与键盘焦点滚动一起裁掉，属于把症状藏起来。

**被否决的方案**

- *只跟随系统，不提供手动切换*：实现最省，但系统偏好不等于阅读偏好；运营台已有手动切换，公共站没有会让「两套 bundle」再次分叉。
- *在 React 挂载后设主题*：能读到 `localStorage`，但首帧已经画完，深色用户必然看到闪白；这是主题切换最典型的失败模式。
- *用 `light-dark()` 重写全部颜色*：需要把每个颜色声明都改成函数形式，且 alpha 洗色、分布条仍要逐条给两套值；改动面远大于新增 7 个令牌，收益只是少一个 `[data-theme]` 块。
- *提高 `admin/theme.css` 的选择器或加 `!important`*：把冲突从「特异度」升级成「特异度 + 顺序 + 重要级」，下一个人更难判断；且运营台与公共站共用 `data-theme`，语义上没有赢家。
- *给 `/e/<slug>.html` 加内联启动脚本*：见上，破的是门禁与对外承诺，不是一行代码。
- *让 `.scrubber` 换行或缩小按钮*：会改变年份索引的交互形态（横向扫视变多行堆叠），也改变页面高度；溢出是栅格项的问题，不该由组件背。
- *用 `overflow-x:hidden` 掩盖溢出*：会让 `scrollWidth === clientWidth` 的断言「变绿」，但侧栏 sticky 与键盘滚动被裁掉，问题仍在。

### 4.3 关键实现细节

**时代分带的区间算法。** `SideRail` 用 `eraIndex = ERAS.findIndex(entry => entry.from === era.from)` 定位当前段，`upper = eraIndex <= 0 ? 当前年 : ERAS[eraIndex - 1].from - 1`。15 段倒序排列后：1912 年落到 index 14，上界是 `ERAS[13].from - 1 = 1950 - 1 = 1949`；2026 年落到 index 0，上界取当前年。**没有硬编码 1949**，下一个分带追加时区间会自动重算。

**主题的启动与运行期分工。** 首屏脚本只做三件事：安全读取 `aihist.theme`（`try/catch`，隐私模式或内嵌 WebView 下 `localStorage` 可能抛错）、决定 `dark` / `light`、写 `dataset.theme` 与 `theme-color`。React 侧 `useTheme()` 的初始值**读已经写在 `<html>` 上的属性**，不再自行判断一次，避免首帧与脚本结论不一致。手动切换走 `applyTheme(theme)`，写入存储；系统偏好变化走 `applyTheme(systemTheme(), false)`，只在没有手动选择时生效，且不落盘——读者没有做选择，就不该把当时的系统状态固化成选择。

**七个令牌的取值与理由。**

| 令牌 | 浅色 | 深色 | 为什么不能只换主色 |
|---|---|---|---|
| `--wash-accent` | `rgba(166,56,43,.045)` | `rgba(211,112,95,.08)` | 红色洗色叠在近黑纸面上会消失，深色需要提高 alpha 并换成更亮的红 |
| `--wash-ink` | `rgba(28,26,23,.04)` | `rgba(236,230,217,.035)` | 深色下「墨」是浅色，洗色必须反过来提亮 |
| `--row-hover` | `rgba(28,26,23,.022)` | `rgba(236,230,217,.05)` | 近黑底上的 2.2% 黑几乎不可见，需改为浅色 alpha |
| `--scrim` | `rgba(28,26,23,.52)` | `rgba(0,0,0,.68)` | 深色页面需要更重的遮罩，否则对话框背后仍亮 |
| `--bar-model` | `#3d372e` | `#cfc6b6` | 分布条是实色块，不能靠主色推导；深色下必须整体反相 |
| `--bar-research` | `#6b5f4b` | `#a89b88` | 同上，且要保持三条之间的明度层次 |
| `--bar-opinion` | `#948873` | `#7b7263` | 同上 |

主色板同时换值：纸 `#14120f`、纸深 `#1b1814`、墨 `#ece6d9`、墨浅 `#c2b8a7`、弱化 `#948a79`、分隔线 `#322c25`、强分隔 `#4b4337`、强调 `#d3705f`、强调浅底 `#3b221c`；`--chart-4/5` 两个字面量图表色也改为 `#b3a48b` / `#574e40`。

**`html` 的 `background-color` 不是装饰。** 深色下页面回弹、首屏绘制前、以及内容短于视口时，露出的都是 `html` 的底色；只给 `body` 上色会在边缘闪白。补上之后，`theme-color`、`html` 背景与 `body` 背景三者同色。

**特异度陷阱的具体数字。** 公共站深色块 `:root[data-theme="dark"]` = `(0,2,0)`；运营台别名 `:root` = `(0,1,0)`。后者即使晚导入也赢不了前者。加 `:not([data-surface="admin"])` 后选择器变成 `(0,3,0)`，但它在运营台页面上**根本不匹配**，所以不参与竞争；运营台的 `:root` 与 `:root[data-theme="dark"]` 照常生效。浏览器实测：运营台深色 `--paper` = `#0f1116`、`body` = `rgb(15,17,22)`；浅色 `#f5f6f8`；公共站两边不受影响。两边的存储键也独立：公共站 `aihist.theme`，运营台 `aihist.admin.theme`。

**静态引用页的深色适配。** 页面样式是构建期内联的，因此深色只需在 STYLE 里加一段 `@media (prefers-color-scheme: dark)`，把同一组令牌换值；`.cite` 的白叠层改为 `--cite-wash`（浅色 `rgba(255,255,255,.35)`，深色 `rgba(255,255,255,.04)`）。`theme-color` 用两个 meta 表达：默认 `#f6f2e9`，带 `media="(prefers-color-scheme: dark)"` 的 `#14120f`；浏览器自行选匹配项，不需要脚本。`@media print` 把纸/墨/分隔线强制回 `#fff` / `#000` / `#ccc`，`--cite-wash: transparent`，并隐藏页眉、返回链接与跳转链接——深色页面打印出来仍是黑纸白字。

**静态页为什么坚持不加脚本。** `check-pages.mjs` 的断言是「`scriptTags.length === 1` 且唯一标签是 `type="application/ld+json" data-page-jsonld`」，另有「不得加载外部脚本」「不得有图片请求」「不得有远程 `@import`/`url()`」。这些断言共同保证 `/e/<slug>.html` 是一个自包含、无执行、可被任意环境解析的引用页；运营台的「被引用」指标也依赖它只产生反代日志、不产生 SPA 埋点。加一段主题启动脚本会让第一条断言直接红，放宽它等于改契约，必须同时改 README、检查器与验收标准。本轮选择保住契约，接受「手动选择不跨页」的缺口，并在 README 的站点形态表里只写「默认跟随系统偏好」，不暗示静态页会跟随手动选择。

**窄屏溢出的修法。** 种子覆盖 50 个不同年份（1912–2026），年份索引就有 50 个 `flex:none` 按钮，单个约 38.7px，min-content ≈1936px。`.scrubber` 自己 `overflow-x:auto` 没错，错在栅格项 `main` 的 `min-width:auto` 把这个 min-content 当成整列下限。给 `main` 与侧栏包裹层加 `min-w-0` 后，列可以收缩到视口宽，横向滚动留在 `.scrubber` 内部；819px 与 1400px 两档实测 `scrollWidth === clientWidth`。

**对比度修正。** 未命中来源族从 `--rule-strong`（浅色 `#b9ae9b`，1.96:1）改为 `--muted`：浅色 `#6f675b` 对纸色 **4.99:1**，深色 `#948a79` 对 `#14120f` **5.49:1**，两套主题都过 4.5:1。深色正文 `#ece6d9` 对 `#14120f` 为 **15.04:1**。

## 十一、总结

v0.4.0 结束时，这个站已经能从 Vercel 发到 CDN、把 API 留在原机，但读者看到的仍然只有一张米色纸：系统到了深色模式，页面不跟着变；页眉说档案从 1950 年开始，而种子数据里躺着 9 条更早的条目，最早一条是 1912 年的象棋自动机。这两件事都属于「界面没有承认数据已经存在」。

这次把两件事一起做了。1912 不是改一个页眉数字，而是把起点提成常量、给时代分带补上第 15 段，让页眉、页脚、侧栏从此同源；深色也不是加一套平行样式，而是在同一组令牌上换值，组件一行没改，七个无法推导的洗色/分布条令牌单独命名。真正的难点不在配色，而在运营台：公共站深色块的特异度会压过运营台的变量别名，导入顺序救不了，最后用 `data-surface="admin"` 把「这块表面不归公共站管」写成显式规则，而不是继续堆选择器。

另外两个决定是刻意留下的缺口。静态引用页只用 CSS 跟随系统，不加脚本——因为 `check-pages` 与 README 承诺它不含 JavaScript，这个承诺比「手动选择跨页」更值钱；顺手修掉的窄屏溢出用的是 `min-w-0`，不是 `overflow-x:hidden`，因为后者只会让 `scrollWidth` 好看，却把侧栏的 sticky 一起裁掉。

现在公共站有了与运营台同级的双主题，档案起点与数据一致，窄屏不再整页横滚；还没做到的是手动选择跨到静态页、Safari/打印的真机验证，以及把「首屏脚本与 `theme.ts` 的重复」交给门禁而不是注释。这几项都写进了验收清单，没有藏在总结里。
