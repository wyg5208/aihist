## 二、任务目标

1. **线上反馈**：「后台只有深色背景，缺少浅色背景。」运营台在强光环境、投屏演示和打印场景下不可读，需要一套浅色界面，并且要用的人能自己选，而不是重新编译。
2. **实测前置条件**：本轮开始前按"登录后台实测"的要求检查环境，发现端口上跑的根本不是本仓库代码，需要先纠正这件事，否则后面所有"看起来正常/不正常"的判断都不可信。
3. **聚焦环误读**：登录页账号框在 autofocus 下会立刻亮起一圈砖红描边，与"输入有误"的红框完全同色；浅色主题下这个误读更明显。这是加浅色时被放大的既有缺陷。

## 三、问题诊断

### 1. 只有一套调色板

| 现象 | 原因 |
|---|---|
| 后台无浅色可选 | `src/admin/theme.css` 把深色令牌直接写在 `:root` 上，全站只有一份值，连"第二份值写在哪里"的位置都没有 |
| 即使覆盖 `:root`，胶囊和提示条仍是深色 | 状态色不是令牌：`StatusPill`、`Notice`、`Overview` 的告警条、`Traffic`/`ApiKeys` 的告警框、`Field` 的 danger 悬停，共 **18 处十六进制字面量**（`#16241b` / `#4a2a25` / `#2c2415` 一族）。这些是"深色底 + 同色系描边"成对出现的，只改文字色会让浅色主题长出一片巧克力色块 |
| 对话框在浅色下像挖了个洞 | 遮罩写死 `bg-black/60`、`bg-black/55`；阴影写死 `shadow-black/70`、`shadow-black/60`。浅色页面上 60% 黑遮罩过重，阴影则发脏 |

### 2. 主题选择没有落点

| 现象 | 原因 |
|---|---|
| 登录页切了主题，进后台又变回去 | 没有持久化载体，切换只存在于 React 内存 |
| 刷新后永远是深色 | 同上；且没有任何"跟随系统"的默认值 |
| 将来若在 React 里设置初始主题，会先闪一下深色再变白 | 首次绘制时样式表已按默认值上色，`useEffect` 在那之后才跑。防闪必须发生在解析 CSS 之前 |

### 3. 聚焦环与错误态同色

`:is(a, button, input, select, textarea, [tabindex]):focus-visible` 的描边用的是 `--c-accent`（砖红 `#d4573f`），而 `--c-danger` 在深色主题里是同一个值 `#d4573f`。也就是说"我正在输入"和"这里出错了"在深色下是同一个颜色，靠形状区分。这在深色下勉强成立，在浅色下不成立。

### 4. 端口上跑的不是这套代码

| 现象 | 原因 |
|---|---|
| `GET /api/v1/admin/overview`、`/admin/keys`、`POST /track`、`/go/nope` 全部 404，只有 `/api/v1/status` 正常 | 8000 端口上的 uvicorn（pid 13024，14:42 启动）加载的是更早的代码，没有 `admin_ops` / `admin_commercial` / `track` / `redirect` 这些路由 |
| `5173/admin/` 返回 `theme-color #f6f2e9`、`color-scheme light`、入口 `/src/main.tsx` | 5173 上的 vite（pid 12268，昨日 00:52 启动）命令行指向 `C:\Users\Administrator\Documents\Qoder\2026-10-23\8b5c5987` —— 另一个目录的旧副本，源码早已不在那里，进程仍持着旧句柄 |

处置：停掉这两个残留进程，分别以 `backend/` 和仓库根为工作目录重启。重启后同一组探测全部符合预期（见第六节），这才使"能登录实测"成立。

## 四、方案与实施

### 4.1 核心取舍

**令牌三段式，别名只写一次。**

```css
:root { /* 公共别名：--paper / --ink / --primary / --sidebar… 全部指向 --c-* */ }
:root, :root[data-theme="dark"] { /* 深色值 */ }
:root[data-theme="light"] { /* 浅色值 */ }
```

别名层只声明一次并引用 `--c-*`，而 `--c-*` 在 `:root[data-theme=light]` 上被覆盖。由于两者作用在同一个元素（`html`）上，变量解析取最终值，所以一份别名自动跟随两套调色板。`globals.css` 里被复用的 `--paper` / `--ink` / `--ring` 因此无需按主题重写。

**状态色按"底色 + 描边 + 悬停底色"三元组令牌化**，而不是给组件加条件类。三者在两个主题里必须成对翻转，缺一个就会出现"浅底深边"的错位。

**首帧由 `admin.html` 的内联脚本决定，React 只负责后续切换。** 脚本读 `localStorage`，没有再读 `matchMedia("(prefers-color-scheme: light)")`，然后写 `documentElement.dataset.theme` 并同步 `meta[name=theme-color]`。它跑在样式表求值之前，所以两套主题都不会闪。

**聚焦环改用中性色，并且每个主题各取一个值**：深色 `#a9b3c2`、浅色 `#3f4754`。都朝向各自主题的文字色，既不与 `--c-info` 抢"信息"语义，也不会在空输入框上被读成校验失败。

**被否决的方案**

- *只加 `@media (prefers-color-scheme: light)` 覆盖*：永远只能跟随系统，用户无法手动选，也无法记忆。需求方要的是"能切"。
- *给每个组件补 Tailwind `dark:` 变体*：本仓库未配置 `darkMode` 策略，`dark:` 前缀当前是死类名；即便配置成 `[data-theme=dark]` 策略，也会把配色散落到 14 个页面里，而本次的核心问题恰恰是"颜色散落"。
- *在 React 里设初始主题*：首帧必闪，且 `theme.ts` 与内联脚本会各写一份默认值判断，两处逻辑迟早分叉。
- *聚焦环用蓝色*：控制台里蓝色已被 `info` 语义占用（信息胶囊、提示条、图表第二条线）。再蓝一次会让"这是提示"与"我在这里"混为一谈。
- *遮罩继续用 60% 黑*：浅色主题下遮罩会把整页压成灰色，读者无法判断后面是什么页面。

### 4.3 关键实现细节

**浅色不是纸白。** 取值 `--c-bg: #f5f6f8`、`--c-surface: #ffffff`、`--c-surface-2: #eef1f5`、`--c-line: #e3e7ec`。理由是前台（`globals.css`）是"纸本年鉴"纹理，控制台要保留"这是另一件工具"的区隔；纯白还会让白色卡片失去层次，只能靠阴影硬撑。

**accent 在浅色下要加深。** 砖红由 `#d4573f` 调到 `#bf4430`，白字对比度因此从 2.9:1 提到 5.2:1。`--c-on-accent` 在深色下是 `#101216`、浅色下是 `#ffffff`——同一个主按钮，两套主题必须换文字色，否则浅色下白字红底只剩一片糊。

**浅色状态色整体降饱和、提亮度**，例如 danger 底 `#fceceb` / 边 `#f0c7c1`、warn 底 `#fdf3e1` / 边 `#ead2a5`。深色的 `#241514` 这类值直接搬到浅色会变成脏棕。

**两个文件共享一份约定。** `admin.html` 与 `theme.ts` 必须使用同一个存储键 `aihist.admin.theme` 和同一组 `theme-color`（`#0f1116` / `#f5f6f8`）。两处都写了注释指回对方，因为这种"跨语言常量"最容易在后续重构里悄悄分叉。

**存储异常按可用性处理。** 隐私模式或内嵌 WebView 下 `localStorage.setItem` 会抛异常，`applyTheme` 捕获后继续应用主题，只是不持久化——不让"记不住"升级成"切不了"。

## 十一、总结

v0.2.0 的运营台只有一种读法：深色。它的颜色也散在 18 处字面量和 6 处黑色遮罩/阴影里，浅色不是一个开关能打开的——那会得到一片深色巧克力块。这次先把颜色收进令牌层（别名一份、值两份），再加上"首帧前决定、切换后记住"的主题开关，顺手把与错误态同色的聚焦环换成中性灰。现在同一个后台有两种完整读数，且维护面从"14 个页面的色值"收敛到"`theme.css` 里两张表"；下一个主题（比如高对比度）只需要再写一段 `:root[data-theme=…]`，不必再翻页面。
