## 2. 任务目标

用户要求做对等的友情互链。

- **AI 素养学习站**（https://ai-edu.pw，独立 AI 素养培训学习平台）与**AI 素养考核站**（https://ai-skill.pw，独立 AI 素养考核认证平台）都已经在自己的**顶栏和页脚**回链「AI 纪年 / 人工智能发展编年史」（aihist.net）。
- aihist 侧此前是**零回链**，链路是单向的。本次在公共站三套版式的页脚底部补上一行「相关站点」，把两条链路补成对等。
- 约束：只动前端可见区块和 README，不碰后端、规则、种子、golden、迁移与公开接口。

## 3. 问题诊断

| 现象 | 原因 |
| --- | --- |
| 两站到 aihist 有链，aihist 到两站没有 | 公共站从来没定义过「站外链接」这一层。三套版式的页脚都是各自手写的内链 JSX（`FootColumn` + 一堆 `/api/v1/*` 与 `#timeline`），没有任何数据结构承载外站条目，新增一个外链只能在三个文件里各写一遍 |
| 直接往底栏里塞两个 `<a>` 会串语义 | 三份页脚的底栏都是「`border-t` + 一行 flex 折行」，里面放的是 `©` 与站内操作（订阅更新 / API 申请 / 发现错误）。「相关站点」是**出站**入口，和站内操作混在同一行，读屏与视觉层级都会错位；底栏也没有为新的语义行留插入位 |
| 三处各写一遍必然漂移 | `target="_blank"` 要配 `rel="noopener noreferrer"`，漏一处就是一个安全缺口；站点文案、域名、简介也会随三个文件各自演化。根因是缺少共享组件与单一数据源 |
| 三套版式的落点前置节点并不相同 | 「采集 / 边界」两段正文只存在于典藏与博物馆版式；极光版式的页脚是「四栏 grid（品牌 + 浏览 + 开放 + 每周简报）＋ 底栏」，它没有那两段。所以不能写「插在采集说明之后」这种依赖前置兄弟节点的定位 |

## 4. 方案与实施

### 4.1 核心取舍

1. **数据与呈现分开，而不是三份复制粘贴**。`src/lib/sisterSites.ts` 是标签、简介、域名、外链的唯一数据源；`src/components/FooterSites.tsx` 是唯一的结构与无障碍契约；三套版式只传一个 `tone`。这样 `target`/`rel`/`title`/`aria-label` 全站只有一处实现。
2. **颜色交给主题，不写死新色**。组件只接收 `tone`，`TONES` 里三套各给 `rule`/`label`/`chip`/`name`/`domain` 五个类名，取各自页脚已有的令牌或色值（极光用 `--rule` / `--muted` / `--ink` / `--rule-strong`，典藏与博物馆用页脚里既有的 `#2a3a4d` / `#26463a` 系列）。没有为这个区块引入任何新令牌。
3. **独立成一条横条，而不是并进底栏**。`FooterSites` 自带 `border-t`，落在「采集 / 边界」正文（极光是四栏 grid）与 `©` 版权行之间，形成「正文 → 相关站点 → 版权」三段。同时把底栏的上边距从 `mt-5` / `mt-6` / `mt-8` 统一收到 `mt-4`，避免两条相邻分隔线之间叠出一大段空白。
4. **纯 `<a>`，不引入路由或点击副作用**。没有埋点、没有 `?ref=` 参数、没有 `window.open`。

| 文件 | 变更 |
| --- | --- |

### 4.3 关键实现细节

- **外链契约**：`href` 取 `SISTER_SITES[].href`（`https://ai-edu.pw` / `https://ai-skill.pw`，浏览器解析后带尾斜杠），`target="_blank"`、`rel="noopener noreferrer"`；`title` 用站点简介，`aria-label` 用 `名称 · 简介（新标签页打开）`——读屏用户在跳转前就知道会离开本站。
- **样式**：`rounded-full` 圆角胶囊（计算值被浏览器钳到 `33554432px`），`text-[12.5px]`，名称 `font-semibold` + 域名 `font-mono text-[10.5px]`，末尾 `↗` 带 `aria-hidden="true"`，hover 时描边变亮并让箭头轻移 `-translate-y-0.5 translate-x-0.5`。
- **小标题**：`font-mono text-[10.5px] uppercase tracking-[0.18em]`，与三套页脚里「采集 / 边界」的标签同一套排版语言。
- **范围**：该区块只在 SPA 主时间轴出现。`/e/<slug>.html` 静态引用页不含 JavaScript、也没有页脚，因此不涉及。

**被否决的方案**

- **在三份 footer JSX 里各写两个 `<a>`**：三处 × 四个属性，`rel` 漏一处就是安全缺口，文案与域名也没有单点可改；README 只能写「见三个文件」。
- **塞进四栏页脚的某一栏**（例如「开放」栏下加一行）：看起来像站内导航，实际是站外；而且三套版式的栏数量与栏标题不同（极光四栏、典藏与博物馆的栏结构另有一套），落点无法统一。
- **把 `SISTER_SITES` 直接塞进维表或后端接口**：这是静态的、一次发布就固定的两个外链，走接口只会多一次请求和一份可空字段，违反「能不加接口就不加」。
- **加 `?ref=aihist` 之类追踪参数**：两站没有对应的统计口径，加了只是污染 URL；若将来需要计量，应在两站侧用 UTM 或 referrer 统计，属于独立决策。
- **把 `title` 与 `aria-label` 合并成一句**：`title` 是悬停提示（简短简介即可），`aria-label` 必须额外说明「新标签页打开」，两者职责不同，合并会牺牲其中一边。

## 7. 发布与回滚

- **静态站（Vercel）**：随 push 自动部署，无需环境变量或构建参数变化。发布后复核：线上任意一套版式滚到底部，页脚应出现「相关站点」一行，两条链接在新标签页打开；三套版式分别在右上角切换后各看一遍。
- **API 服务器（Windows）**：**不重启、不部署**。本轮没有任何后端代码、迁移或 nginx 配置变化。
- **SQLite 备份**：本轮无库变更，未执行备份。
- **回滚**：`git revert` 该次提交（或 Vercel 回滚到上一次部署）即可；无数据副作用、无接口兼容性问题，回滚后两站仍能正常回链 aihist。

## 11. 总结

页脚从「只有站内入口」变成「站内入口 + 一条对等的友链出口」：两站在顶栏和页脚回链 aihist，aihist 现在也在三套版式的同一位置回链它们。更重要的是这件事不是靠三份复制粘贴完成的——外链契约（新标签页、`noopener noreferrer`、含「新标签页打开」的 `aria-label`）和站点文案各只有一个来源，将来改名、换域名或加第三个友站，都只需要动 `src/lib/sisterSites.ts`，不会在三套版式之间漂移。
