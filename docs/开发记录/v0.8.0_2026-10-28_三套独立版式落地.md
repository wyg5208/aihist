| 产品版本 | v0.7.0 → **v0.8.0**（minor：把"三套配色"升级为"三套独立版式"，属于新增能力） |

| 升级理由 | v0.7.0 交付的是"一套骨架 + 三套令牌"，用户指出要的是 `demos/ui/` 里三份 DEMO 各自成页：文案、结构、视觉语言都不同 |

记录开始前的状态：v0.7.0 已经把 `demos/ui/` 里第 1/3/5 号方案的**调色板**接进站点，但三者共用同一段 DOM：一个 56px 顶栏、一份 `Masthead`、一份 `EventRow` 列表。用户的原话是"包括文字、布局结构、色彩主题样式都要三套，和 DEMO 一致，而不是仅仅是一套结构三套主题样式"——即三份 HTML 原型要被实现成三张不同的页面，而不是三份 CSS 变量表。

## 二、任务目标

1. 把 `01-editorial-grand.html`（典藏卷轴）、`03-dark-aurora.html`（深色极光）、`05-museum-warm.html`（博物馆暖调）分别实现为 **一套完整版式**：各自的骨架、文案与视觉语言。
2. 右上角切换器切过去之后，**换的是页面**，不只是颜色；选择仍写 `localStorage['aihist.theme']`，首帧仍由 `index.html` 内联脚本决定。
3. 三套版式共用**一个数据控制器**：切版式不丢筛选、不丢展开态、不丢 `?e=<slug>` 深链。
4. 删掉为此而生的旧共享组件与随之失效的样式、令牌、字段，不留死代码。
5. 运营台 `/admin/` 一行都不许动。

## 三、问题诊断

| 现象 | 真实成因 |
| --- | --- |
| 点切换器只换颜色，版式纹丝不动 | `ThemeSwitcher` 与 `App` 各自调用一次 `useTheme()`，各自持有一份 `useState`；`applyTheme` 只写 `documentElement.dataset.theme` 和 `localStorage`，没有订阅者。于是写属性的组件重渲染、画页面的组件不知道 |
| 三套仍是"同一页" | v0.7.0 的取舍是"一套结构、三套令牌"，三份 DEMO 的几何完全不同：头部 34+68px / 70px / 32+74px，首屏 424 / 583 / 619px 高，列表是 91px 细行 / 98px 三栏行 / 677px 两列卡片。一套骨架靠变量表达不了这些差异 |
| 三份 DEMO 的文案在代码里找不到对应字段 | 列表接口 `/api/v1/timeline` 的 `timeline_item()` 不返回 `summary`，DEMO 里每张卡片下面那段摘要没有数据源 |
| 展开条目的取数逻辑只能服务一个列表 | 展开态、详情缓存、失败重试都写在 `App.tsx` 里，一旦要渲染三段互不相同的列表，这份逻辑要么复制三份、要么抽出来 |
| 组件删了、样式还在 | `globals.css` 单文件承载全站，`Masthead`/`EventRow`/`FilterBar`/`SideRail`/`SyncPanel` 等被移除后，其样式与令牌失去消费者；同时三套视图又新增了大批 `.ed-*`/`.au-*`/`.mu-*` |

**一个必须先解决的工程约束**：主题不再只是"配色"，它同时决定"渲染哪套版式"。所以主题值必须是**共享外部状态**，由切换器与外壳共同订阅；组件本地 `useState` 在这套设计下一定出错——这正是 v0.7.0 遗留的真实缺陷（上一轮只验证了 `data-theme`、`aria-pressed`、`localStorage` 三处同步，没有验证 DOM 是否换成另一套）。

另一个约束是运营台：公共站的三套令牌继续带 `:not([data-surface="admin"])` 守卫；新增的 `.ed-*` / `.au-*` / `.mu-*` 只在公共页面渲染，admin 入口自己的 `theme.css` 与类名不受影响。

## 四、方案与实施

四个取舍：

1. **三套组件树，而不是一套骨架加条件分支**。`src/views/{EditorialView,AuroraView,MuseumView}.tsx` 各自完整拥有头部、首屏、筛选、列表与页脚。代价是三份代码有相似片段（筛选 chips、状态占位、订阅块），收益是任何一套都能照 DEMO 调整而不牵动另外两套。
2. **主题抽成模块级外部 store**（`subscribeTheme` + `useSyncExternalStore`），而不是 React context。切换器在页头、外壳在根部，二者是邻里关系而非父子关系；store 让"谁改、谁看"与组件层级解耦，也避免为一个布尔以外的东西引入 Provider。
3. **数据控制器唯一，视图可替换**。`useArchive()` 从 `App.tsx` 抽成 `src/hooks/useArchive.ts`，一次 `useArchive()` 调用喂给当前视图；切版式是换视图组件，控制器实例不变，因此筛选、展开、深链都留着。
4. **列表没有 `summary` 就不编数据**。三套版式需要的摘要一律由真实字段拼装（博物馆版用「证据来自{来源类别}，共 N 条链接 · 重要度 X / 100。」），不改后端契约、不重导 golden、不动 parity 测试。

被否决的方案：

- **在 `App.tsx` 里按主题 fork 三段 JSX**：单文件会到 1400 行以上，三套的 sticky 层级与栅格互相污染，且任何一次改动都要读三遍上下文。
- **三份 DEMO 原样搬进 iframe 或静态页**：切换要重新加载、无法共享筛选与深链，也拿不到实时接口。
- **给列表接口加 `summary` 字段**：向后兼容，但属于契约变更（golden 重导 + `nowMs` 变化 + parity 断言），与本轮"纯前端"的定位冲突，留作下一步候选。
- **每套视图各自 `fetchEvent`**：切一次版式会把已展开的条目重新请求一遍，还会让缓存随着视图数量翻倍。

### 4.2 主题共享 store

```ts
const listeners = new Set<() => void>();
export function subscribeTheme(listener: () => void) { watchSystem(); listeners.add(listener); return () => listeners.delete(listener); }
export function applyTheme(theme: Theme, persist = true): Theme { /* dataset + meta + storage */ emit(); return theme; }
```

`useTheme()` 从"本地 state + effect"改成 `useSyncExternalStore(subscribeTheme, currentTheme, currentTheme)`，`setTheme` 直接调 `applyTheme`。`watchSystem()`（系统偏好变化、未手动选过时跟随）被挪进订阅的首次调用，只在真的有人订阅时才挂监听。`currentTheme()` / `applyTheme()` 加了 `typeof document === "undefined"` 守卫，服务端或测试环境不再直接崩。

`index.html` 未改：首帧仍由那段内联脚本写 `data-theme`，所以"三套版式不闪"依赖的还是同一处，React 侧只读结果。

### 4.3 详情取数：按需 + 模块级 LRU

`useEventDetail(id, expanded)` 把展开取数从 `App.tsx` 里抽出来：只有展开过才请求，结果进一个 48 条的模块级 `Map`（LRU，`remember()` 里删旧插新），所以"展开 → 折叠 → 再展开"和"切到另一套版式再切回来"都不再打第二次请求。

### 4.4 数据与文案

- `useArchive()` 成为唯一控制器（337 行），返回 `items / groups / years / activeYear / jumpTo / query / category / confidence / keyword / vendor / series / 各 setter / clearFilters / categoryCounts / vendorOptions / expandedId / toggleRow / panel / recent / ...`，`ArchiveController` 类型由它反推，三套视图只吃这一个入参。
- `src/lib/cadence.ts` 的 `quarterSlots(items, span = 8)` 只算一次"最近八个季度的收录节奏"，供极光版两条 sparkline 使用。
- `src/lib/format.ts` 新增 `shortDate`（按精度截断，年份级不假装有月日）与 `splitDate`（典藏日期列要"粗日 / 细年"两行），`CATEGORY_META.milestone.short` 从「里程」改回「里程碑」。
- 三套的订阅块共用 `src/components/SubscribeForm.tsx`（114 行，`POST /api/v1/subscribe`，`source` 区分触达点），样式由调用方传入 `inputClass` / `buttonClass`，因此三套的输入框形状（方 / 圆角 / 胶囊）各自成立。

aurora    @1440  rows 0   / cards 0   / auroraRows 158

## 十一、总结

这轮改的不是"多两套皮肤"，而是**把"配色"这个维度换成了"版式"这个维度**。v0.7.0 之所以被退回，根因不是颜色没调好，而是把三张设计稿压缩成了一套骨架的变量表——一旦压缩，DEMO 里那些真正决定气质的东西（三层 sticky、印章、季度 sparkline、卡片网格、每页自己的那段话）就无处安放。

第二个收获是那个**"切换器只换颜色"的缺陷**：它一直存在，只是上一轮的验证清单只覆盖了属性、`aria-pressed`、`localStorage` 和 `theme-color` 四处写入——全都在"写"的一侧，没有一条断言问"页面变成另一套了吗"。这次换成 `useSyncExternalStore` 之后，切换器与外层外壳天然同源；验证也改成了直接数 DOM（`rows` / `cards` / `auroraRows`），而不是相信存储里写的值。
