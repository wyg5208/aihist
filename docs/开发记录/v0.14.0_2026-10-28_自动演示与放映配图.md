## 2. 任务目标

用户的原始诉求是一件事的四层：

> 能否增加一个自动演示功能（类似 PPT 翻屏，左右切换），用户可以选择 全程 或 某个期间（比如 2023年1月到2026年4月），每个页面只显示一个记录，最好配图（需要检索 下载 截图 或文生图创作）

拆开是四个必须同时成立的条件：**可自动播**、**区间可选**、**一屏一条**、**有图**。用三个问题定了三个方向：

| 项 | 口径（已确认） |
| --- | --- |
| 配图策略 | 程序化图版打底 + 真实图逐步补（不追求一次性全站配图） |
| 入口形态 | 站内全屏浮层 + 可分享链接（不加路由、不新增静态页） |
| 放映外观 | 跟随当前三套版式（典藏 / 极光 / 博物馆），不做独立的放映皮肤 |

第三项决定了整个实现的位置：放映层必须**架在三套版式之上**，而不是塞进其中一套。

## 3. 四个设计判断

### 3.1 区间用月序号比较，但年精度条目按年命中

`sortDate` 恒为完整 ISO 日期，`datePrecision` 才是「这条记录知道到什么粒度」。把 `1956-01-01` 当成「1956 年 1 月 1 日」去和 `1956-06..1956-12` 比较，会让达特茅斯会议掉出「1956 年下半年」——而档案只知道它在 1956 年。

```ts
export function inRange(item: TimelineItem, range: ShowRange): boolean {
  if (range.kind === "all") return true;
  if (item.datePrecision === "year") {
    return item.year >= from.year && item.year <= to.year;
  }
  const serial = monthSerial({ year: item.year, month: Number(item.sortDate.slice(5, 7)) });
  return serial >= monthSerial(range.from) && serial <= monthSerial(range.to);
}
```

其余一律 `year * 12 + (month - 1)` 求月序号，跨年不需要特判。起止填反不报错，`orderRange` 直接对调——放映厅不是表单校验器。

### 3.2 图版必须确定性，且不描摹史实

158 条记录没有一条有图片字段，也不可能都拿到可授权的照片。图版因此是**基底**而不是占位符：

- **确定性**：FNV-1a 哈希 slug 得种子，xorshift32 展开，同一 slug 永远得到同一张图版。翻到 37 屏和翻回 12 屏看到的是同一个编号 `No.583`。
- **母题来自类别**：`model` → 光阑、`research` → 轨道、`milestone` → 爆发、`policy` → 柱列、`opinion` → 气泡。类别是档案自己的事实，比随机几何更有信息量。
- **不描摹史实**：纯几何 + 年份水印 + sparkline + 裁切标记。图注固定写「编年图版 No.xxx · 依类别与标签生成」——它是图版，不是照片，也不假装是。
- **颜色走变量**：`--plate-bg / --plate-ink / --plate-accent` 三个令牌跟着三套主题走，图版不需要知道当前是哪一版。

### 3.3 放映层用一个 `<dialog>`，三套版式零改动

三套版式各自实现顶栏与骨架，逐个改三份是纯重复劳动。放映厅因此放在 `App.tsx` 一层：

```tsx
<dialog ref={dialogRef} className="show-dialog" onClose={show.close} onKeyDown={onKeyDown}>
```

用原生 `<dialog>` 的 `showModal()` 换来焦点陷阱、背景 inert、Esc 关闭三件事，和站内既有的 `StandardDialog` 是同一套路数。里面只有两种画面——「选区间」与「一屏一条」——翻页、暂停、全屏、分享都在这层收口。

摘要不在 timeline 接口里（`TimelineItem` 没有 `summary`），按屏拉 `EventDetail` 会先空一行再填字，所以给 `useEventDetail` 补了 `prefetchEvent(id)`，放映时预取当前屏与下一屏。

### 3.4 分享链接用 `?show=`，不新增路由

```
/?show=all
/?show=2023-01..2026-04
/?show=1956            ← 裸年份按整年解释
```

`history.replaceState` 写入，保留 `?e=` 等其它参数；读不懂的值（`?show=nonsense`）在数据到位后**从地址栏清掉**，而不是留一个看起来像能用、实际被忽略的参数。静态页与 sitemap 不受影响：`?show=` 不是独立地址，不进 sitemap。

## 4. 配图：三层与一次落地

### 4.1 三层

| 层 | 作用 | 位置 |
| --- | --- | --- |
| 登记图 | 有出处的真实图或示意图，显示即带图注 | `src/data/visuals.json` + `public/visuals/` |
| 程序化图版 | 未登记条目、或登记图加载失败时的兜底 | `src/components/VisualPlate.tsx` |
| 降级链 | `img.onError → 退回图版`，放映永远不出现破图 | `ShowSlide.tsx` |

登记项必须写全 `alt / credit / license / kind`。理由写在 `visuals.ts` 的注释里：编年史站点的图片一旦说不清来历，比没有图更伤可信度。

### 4.2 首批 14 张：AI 生成示意图

选条目看两件事——**故事线上的关节**与**类别的覆盖**，最终 14 条横跨 1950–2025、覆盖全部五个类别：

| 1997 | `deep-blue-1997` | milestone | 棋局与 1990 年代主机 |

边界写清楚：

- **全部标注 `kind: "illustration"`、`license: "非史实照片"`**，图注在画面上常驻「AI 生成示意图 · 非史实照片」。示意就是示意，不借历史照片的权威。
- **不画真实人脸、不写文字**。生成的字母必然是乱码，人脸会把示意图变成不可信的历史还原。
- **统一暖纸底 + 墨线 + 单点朱红**，与三套主题都能共存（极光下像灯箱里的图版，博物馆下与亚麻纸同色系）。

### 4.3 体积：23 MB → 1.9 MB

生成物是 1024×1280 的 PNG，14 张合计约 23 MB。仓库和后端 venv 都没有现成图像库（Pillow 未安装），用 `System.Drawing` 统一降到 900×1125、JPEG 质量 88：

## 6. 踩坑与修正

1. **设定页首版撑出竖向滚动条。** 单列表单靠左、右侧大片留白，浏览器仍认为内容超出一屏。改成两栏（表单 + 300px 宽、3:4 的节目单预览）并把 `.show-setup` 收进 `max-width: 1240px` 居中后消失——预览本身也成了信息，不只是填空。
2. **放映正文行宽接近 790px。** 长摘要一行读下来会串行，给 `.show-copy-inner` 加 `max-width: 660px`。
3. **空区间的提示是「按 8 秒一屏约需 0 秒」。** 数字没错，话是错的；改成「该区间没有记录 · 换一段区间或选「全程」」，同时把开始按钮文案换成同名状态并禁用。
4. **读不懂的分享链接留在地址栏。** 解析失败时只 `return` 会让 `?show=nonsense` 看起来生效。改为 `writeShowQuery(null)` 就地清掉。
5. **第一版达特茅斯图版是 3D 渲染观感。** 其余 13 张是墨线平涂，混进一张带透视光影的会像另一个产品。prompt 里补「NO 3D render / NO photographic lighting」重生成。**同一轮还误用了 1024×768 横图**——竖版画框会 `cover` 掉两侧，最终统一 1024×1280。
6. **生成接口失败一次（`40500 generate image error`）。** 重试即成功。生成式资源要按「一次失败不代表缺陷」处理，不要为它改设计。
7. **PNG 直进仓库会让静态资源膨胀 12 倍。** 生成物是给人看的底稿，不是交付物；进 `public/` 之前必须降采样与转码，并且只登记转码后的路径。
8. **压缩后生成器水印被裁掉。** 不是有意去水印，是 `cover` 的副作用；因为图注本来就要写「AI 生成示意图 · 非史实照片」，出处不依赖水印，所以不补。

## 10. 下一步

**短期**：

1. **用可授权的真图替换部分示意图。** 优先顺序是官方新闻稿配图（`kind: "photo"`，注明「官方新闻稿」）→ 官方界面截图（`kind: "screenshot"`，注明「本机截图」）。`visuals.json` 是唯一改动点，换图不需要改组件。
2. **补余下条目的示意图**，按年代密度排：2023–2026 每屏都进入投影的概率最高，先补这一段。
3. **预取下一屏的图片。** 现在只预取 `EventDetail`，图片靠浏览器首次请求；若翻页时出现空白，就在 `useShow` 里对 `upcoming` 的 `visualFor` 做一次 `new Image().src`。

**中期**：

1. **把放映当作推广素材生成器**：固定区间 + 截图 = 一组可直接发 CSDN 的图文。
2. **图版与登记图的过渡**：同一场放映里两种视觉并置，最好在版式上给「这是示意图」与「这是图版」同一个落款位置——目前已经共用 `.show-credit`，但字号与对比度还可以更统一。
3. **更多放映参数**：只播某一类别（例如只看 `policy`）现在是靠区间间接实现的；若用户真这么用，再加一个类别开关。

## 11. 总结

这一轮把「读档案」变成「看档案」：同一个时间轴，可以按自己的区间一屏一屏走下去，也可以把那段区间直接发给人。三件事保证了它不会变成一次性演示——区间按精度解释（元年条目不会被月份规则伤害）、图版按 slug 确定（同一场放映永远长一样）、放映层与三套版式解耦（换皮肤不用改放映）。
