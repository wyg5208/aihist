## 二、任务目标

v0.6.0 收尾后，用户提出三点界面反馈：

1. **页底能否始终显示**——页脚那行入口（收录标准 / 订阅更新 / API 申请 / 发现错误）不要随开关或状态消失；
2. **文字整体偏小**——尤其等宽标签、元信息、页脚链接；
3. **利用全宽，屏幕两侧还有空白**。

目标是把阅读密度让给内容，同时不破坏"纸面档案"的版式语言（无卡片、无阴影、只用线与字号建立层级）。

## 三、问题诊断

| 现象 | 原因 |
| --- | --- |
| 1920 宽屏下内容两侧各空约 370px | 主容器写死 `max-w-[1180px]`，没有断点放宽；右侧栏固定 `18.5rem` |
| 大量标签"看得见但费眼" | 组件里密集使用 `text-[9px]` / `text-[10px]`；`globals.css` 的 `.filter-chip` 10px、`.chip-count` 9px、`.prose-note` 12px、`.detail-meta dt` 9px；`body` 15px |
| 页脚「API 申请」点进去只有一句"当前没有启用" | 链接本身是常驻的（不跟 `OPEN_API_ENABLED` 走），但关闭态页面 `_closed()` 只给了结论，没给下一步，等于死路 |
| 条目详情仍写「三个独立模型分别打分」 | v0.6.0 的 A2 只改了页首与页脚，漏掉评审脚注这一处；同一事实在第三处仍是旧口径 |
| 放大小字后日期列会挤 | `EventRow` 网格列宽按旧字号（10/11px）定死为 `2.7rem / 5.2rem` |

## 四、方案与实施

**取舍一：放宽到 1560/1760，而不是真正 100%。**
`max-w-[1180px] → lg:max-w-[1480px] 2xl:max-w-[1760px]`，内边距 `lg:px-8 2xl:px-10`。100% 全宽在 2560 显示器上会让单行标题跑到 2000px，中文长行反而更难读；两级断点既能吃掉两侧空白，又保留了行长上限。实测 1920 下容器 1760 + 每侧 72.5px 外边距，正文从 112.5px 开始，两侧空白从 370px 降到 72.5px。

**取舍二：整体 +1.5px，按层级等比，不合并层级。**
映射固定为 `9→10.5 / 9.5→11 / 10→11.5 / 10.5→12 / 11→12.5 / 11.5→13 / 12→13.5 / 12.5→14 / 13→14.5 / 13.5→15`，`body` 15→16px、行高 1.6→1.65。只放大正文会让"小字依旧小、大字更大"，层级反而更断层；等比上移保持原有对比关系。批量替换时按字号**从大到小**执行，避免 `9→10.5` 之后又被 `10.5→12` 二次命中。

**取舍三：展开区限宽 58rem。**
主列在 1920 下约 1280px，摘要与证据链单行过长。给 `EventDetail` 外层加 `max-w-[58rem]`——列变宽，但阅读行宽不跟着无限变宽。页眉导语同样限到 46rem。

**取舍四：关闭态仍是 404，但给出出路。**
`/api/v1/open/apply` 在 `OPEN_API_ENABLED=false` 时保留 404（通道确实不存在，且不确认路由存在是有意的），但正文重写为：说明读取接口与申请表同时启用、当前只开放阅读、档案随时可读，并给两个出口（`/api/v1/subscribe?src=apply` 订阅开放通知、`/` 看时间轴）。页脚链接不跟开关走，这是用户明确要的"始终显示"；能做的只是让落点不再是一句话的尽头。

**被否决：固定底部工具条（sticky footer bar）。**
能让入口在滚动中始终可见，但会长期占掉约 40px 视口、遮挡时间轴尾部，且与"纸面档案"的版式（无浮层、只有线与留白）冲突。如果确实需要"滚动时也可见"，应单独立项做成一条极简细条，并同时决定它与右侧 sticky 侧栏的关系。

**关键实现细节**

- `EventRow` 的日期是等宽 + `tabular-nums`，字号从 11→12.5px 后列宽必须跟着加宽，否则日期会折行；展开区左缩进与之同步，避免折叠/展开时标题左缘错位。
- 类别标签是中文 + 大字距，字号增大后必须**收紧**字距（0.12em→0.1em），否则五个字会散成"孤立字符"。
- 关闭态页面不写死条数（不写"158 条"），避免种子增长后文案过期。

## 十一、总结

这次改的是"读得累"这件事：屏幕两端空了三百多像素、而真正要读的字只有 9px——两个极端同时存在，说明版式是照着内容少、字号小的假设定下来的。把容器放宽到 1560/1760 让小字有地方舒展，把 7–12px 的一整层字号等比上移 1.5px，再给超宽屏的展开区一个 58rem 的行长上限，密度上来了、行长没失控。附带修掉第三处"三模型"旧文案，并把申请关口的 404 从"此路不通"改成"这里现在不通，但你可以这样走"。真正欠着的是一次移动端真机目视，以及把这些字号收进 token 表。
