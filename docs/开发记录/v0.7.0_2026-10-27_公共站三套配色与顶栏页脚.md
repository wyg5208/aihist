# v0.7.0 · 公共站三套配色与顶栏页脚

## 一、基本信息

| 项 | 值 |
| --- | --- |
| 产品版本 | v0.6.3 → **v0.7.0**（minor：新增"可切换配色"这一能力，不是修既有缺陷） |
| 日期 | 2026-10-27 |
| 升级理由 | 公共站版式被指出四个问题（配色不大气、缺导航与底栏、条目空间浪费、重要入口难发现），把它们一次性收进三套可切换的配色与一套统一骨架 |

记录开始前的状态：`v0.6.3` 之后公共站只有一个"深/浅"二值切换（`ThemeToggle`），配色是"纸本 + 墨蓝 + 一点红"。用户在原话里点了四件事：颜色不够大气；没有导航栏和底栏，页面像一张长纸；卡片里标签竖着排、一行只放一个，空间浪费；订阅与 API 申请这类要事埋在页面深处，很难发现。

## 二、任务目标

1. 把用户从五个排版方案里挑出的 **1 典藏 / 3 极光 / 5 博物馆** 变成同一套结构的三种皮肤，**用户自己能切**，切换结果记住。
2. 补上 **常驻顶部导航** 与 **四栏页脚**：导航只放真实地址，页脚要把"采集"和"边界"两段正文搬到明面。
3. 压掉条目里的纵向浪费：类别从独立一行并进日期列，置信度 / 机构 / 模型 / 证据数 / 标签并成**一行横排**，展开按钮收成小方块。
4. 让"订阅"和"API 申请"在**四个位置**都能被撞见：顶栏、首屏按钮组、列表末尾的深色条、页脚订阅块，并用 `?src=` 区分触达点。
5. 运营台一行都不许动。

## 三、问题诊断

先说清"为什么不是调几个颜色"。

| 现象 | 真实成因 |
| --- | --- |
| 只有一个二值开关 | `ThemeToggle` 把 `light/dark` 写进 `data-theme`，`globals.css` 里只有两套令牌；再想要第三种皮肤，**没有第三个位置可放** |
| 深色那套"能用但不高级" | 深色是把浅色令牌逐个反相得到的，`--ink` 在深色下变成近白，于是所有"深色块"（页脚、主按钮）都失去了可用的底色——**没有比正文更深的层级** |
| 条目行高不齐、看着松散 | `EventRow` 是三段式：日期列只放日期，类别单独一行，meta 又是另一行；一行条目最高 130px 上下 |
| 入口难发现 | 订阅、API 申请都只出现在页面中段的某个卡片里，滚过就没了；页面既没有常驻导航也没有页脚，滚动位置是唯一线索 |
| 页面两侧留白 | 栅格只有列表 + 右栏，右栏没有高度约束，长列表旁边是一整片空纸 |

**一个必须先解决的工程约束**：运营台与公共站共用 `globals.css`。运营台自己有一套 `light/dark` 令牌（`src/admin/theme.css`），选择器是 `:root[data-theme="light"]` 这一级。公共站的新选择器如果是 `:root[data-theme="aurora"]`（特异度 `(0,2,0)`），字母序上会**压过**运营台的同名令牌，把运营台一起染成极光。所以三套皮肤全部带 `:not([data-surface="admin"])` 守卫。

## 四、方案与实施

三个取舍：

1. **一套结构、三套令牌，而不是三套组件树**。三套皮肤只在颜色、圆角、字体、背景纹理上不同，DOM 完全一致。这样切换是一次属性写入，不重建组件，也不会出现"某套皮肤漏了某个状态"。代价是必须把语义令牌补齐——凡是"某套皮肤里语义变了"的地方，都要有独立的名字。
2. **主题标识换成有名字的三值**，`editorial / aurora / museum`，而不是 `1/3/5` 或 `paper/dark/warm`。编号无法读，颜色名会把皮肤钉死在颜色上（博物馆将来换成米灰也还是博物馆）。
3. **旧值做映射，不做迁移弹窗**：`localStorage` 的 key 保持 `aihist.theme`，读到 `light → editorial`、`dark → aurora`。老用户的选择不会丢，也不会看到"主题已升级"这种提示。

被否决的方案：

- **沿用 `light/dark` 再加一个 `warm`**：`dark` 会同时意味着"极光"和"运营台的深色"，两套语义从此纠缠。
- **把三套皮肤做成三个 CSS 文件按需加载**：切换会闪一帧白，还得处理加载竞态；三套令牌加起来不到 200 行，全部内联更稳。
- **用 `prefers-color-scheme` 决定三套里的哪一套**：系统只表达"亮/暗"，表达不了"极光"。所以系统偏好只用来**兜底初始值**（亮 → 典藏、暗 → 极光），一旦用户点过，就以用户为准。

### 4.1 令牌：把"深色块"从 `--ink` 里拆出来

这是本轮最关键的一处结构改动。原来所有深色块（页脚、主按钮）都用 `--ink` 当底、`--paper` 当字；极光下 `--ink` 是近白、`--paper` 是近黑，这套写法会把页脚变成白底黑字，直接错位。新增：

| 令牌 | 语义 | 典藏 | 极光 | 博物馆 |
| --- | --- | --- | --- | --- |
| `--deep` | 深色带底 | `#0f1c2b` | `rgba(255,255,255,.045)` | `#123a2c` |
| `--on-deep` / `--on-deep-soft` | 深色带上的字 | `#f7f0e0` / `#c9bfab` | `#e9edf8` / 半透明 | `#f3ebd6` |
| `--deep-rule` | 深色带里的分隔线 | 16% 米白 | 8% 白 | 16% 米白 |
| `--cta-bg` / `--cta-ink` | 主按钮 | `--deep` / `--on-deep` | 青紫渐变 / `#080a14` | 同典藏 |
| `--band-btn-bg` / `--band-btn-ink` | 深色带内按钮 | 米白 / 墨蓝 | 半透明白 / 浅字 | 同典藏 |
| `--accent-mark` | 装饰色（色块、下划线） | `#a67c3d` | `#a98bff` | `#b08d4f` |

`--accent` 仍然只承担**文本级**用途，三套都保证与底色对比度 ≥ 4.5:1；需要"更亮但不够黑"的装饰位置一律用 `--accent-mark`，两者分开之后，就不会再出现"为了好看把正文小字染成浅金"的对比度问题。

### 4.2 字体：`@theme inline` 的副作用

极光那套要换字体栈（衬线 → 无衬线 + 负字距）。但 Tailwind v4 的 `@theme inline` 会把字体**字面值**直接内联进 `.font-serif` 工具类，改 `--font-serif` 变量对它无效。所以极光的字体覆盖写成类级覆盖：`:root[data-theme="aurora"]:not([data-surface="admin"]) .font-serif { font-family: <无衬线栈>; letter-spacing: -.02em }`。这是本轮唯一一处"必须绕过设计系统"的地方，已在 CSS 里写明原因。

### 4.3 首帧不闪

配色由 `index.html` 里的内联脚本在模块图之前决定：读 `localStorage` → 映射旧值 → 写 `documentElement.dataset.theme` → 同步 `meta[name=theme-color]`（三套各自的 chrome 色：`#faf7f0` / `#06070d` / `#f4f0e5`）。React 侧的 `useTheme` 只读这个属性的结果，不参与首帧决策，因此不存在"先渲染典藏、再跳到极光"的闪烁。

### 4.4 骨架：顶栏 56px 与四栏页脚

| 组件 | 职责 | 要点 |
| --- | --- | --- |
| `SiteNav`（新） | 常驻导航 | `position:sticky; top:0; height:3.5rem`，半透明 + `backdrop-filter: blur(14px)`；左侧只放真实地址（`#main`、收录标准弹窗、`/api/v1/correct`、`/admin/`），右侧切换器 + API 申请 + 订阅更新 |
| `ThemeSwitcher`（新） | 三选一 | `role="group"` + 三个 `aria-pressed` 按钮，每颗带色块；窄屏只留色块（文字 `hidden lg:inline`），保证 390 宽不换行 |
| `Masthead`（重写） | 首屏 | 顶部元信息行（`Vol. I · 1912—2026` + 同步状态 + 可截断的通知）、`clamp(3.1rem,8.4vw,6.4rem)` 大标题、CTA 三按钮、四格 stat |
| `CtaBand`（新） | 列表末尾的深色条 | 订阅 + API 申请，`?src=band` |
| `SiteFooter`（新） | 四栏页脚 | 关于 / 浏览 / 开放 / 每周一封 + 「采集」「边界」两段正文 + 版权行；内部 `FooterColumn` |

`ThemeToggle.tsx` 删除，`useTheme` 的签名从 `{theme, toggle}` 改成 `{theme, setTheme}`。

滚动层级随之重排：顶栏占 56px，所以年份标题 `sticky top-14`（原 `top-0`，会钻到导航底下）、右栏 `lg:top-14 lg:max-h-[calc(100dvh-3.5rem)]`（既跟手又不再留一片空纸）、`.year-section { scroll-margin-top: 4.75rem }`（锚点跳转不被导航遮住）。

### 4.5 密度：一行条目从约 130px 降到约 96px

- **日期列承载类别**：`grid-cols-[4.8rem_0.75rem_1fr]`（sm 起 `6.2rem_0.9rem_1fr`），日期在上、`■ 里程碑` 在下，省掉单独一行，同时让"哪一年、哪一类"挤在同一只眼睛里。
- **meta 一行横排**：置信度徽章 · 机构 · 模型 · 来源数 · 标签（最多 3 个）在同一 `flex flex-wrap` 里，`+ / −` 用 `ml-auto` 收到右端、加 1px 边框成为"这一行可点"的唯一提示。
- **筛选行合并**：类别 chips 与可信度 chips 原来各占一行，现在是同一 `flex-wrap`，中间用 1px 竖线 + 「可信度」标签分隔。
- **展开详情对齐**：`ml-[6.55rem]`（sm `8.6rem`）正好等于栅格前三列宽度之和，展开后正文与标题左缘齐平。

## 七、发布与回滚

本轮**只有前端**，按既有流程：提交并 push，Vercel 随 push 自动部署；**不需要重启 `aihist-api`，不需要跑迁移**。

发布后线上实测（不可省）：首页三套切换、`/?e=<slug>` 深链展开、`/e/turing-1950.html` 直接打开、`/admin/` 仍是自己的双主题（不被极光染色）、390 宽导航不换行。

回滚三档：

| 档 | 做法 | 代价 |
| --- | --- | --- |
| 整轮 | `git revert` 本提交，Vercel 重新部署 | 回到单一切换器版本，`aihist.theme` 里的 `aurora/museum` 会成为未识别值，`isTheme` 判定失败后按系统偏好兜底——不会白屏 |
| 只保留一个主题 | 把 `THEMES` 收成一项并删掉 `ThemeSwitcher`，`data-theme` 恒为 `editorial` | 保留顶栏与页脚，丢掉切换能力 |
| 只回收配色 | 把 `:root[data-theme="aurora"|"museum"]` 两块删掉 | 令牌与组件都在，但两套皮肤失效，会落回典藏 |

## 九、下一步

1. **发布**：commit → push → 等 Vercel 部署 → 按第七节四项线上实测。
2. **静态引用页要不要跟随站内主题**：`/e/<slug>.html` 是无 JS 的静态页，本轮仍是单套米色 + `prefers-color-scheme`。要跟随用户选择，必须在构建期生成三套或加一段极小的内联脚本——前者体积翻三倍，后者破坏"不含 JavaScript"的既有承诺，留给下一轮决定。

## 十一、总结

这次改动的要点不在"三个皮肤"，而在**把 `--ink` 一物二用的问题拆开**。原来"正文色"同时兼任"深色块底色"，只在浅色主题下成立；一旦引入深色皮肤，这个假设立刻失效，页脚和主按钮会同时错位。拆出 `--deep` 系列之后，三套皮肤才能共用同一份结构，也才有了"配色是皮肤、结构是骨架"这个分层。

第二层是**约束的可见性**：`:not([data-surface="admin"])` 这一串看着啰嗦，但它把"公共站的配色不许外溢到运营台"写进了选择器；`@theme inline` 的字体覆盖旁边也留了原因注释。这类地方如果只靠记忆，下一次加第四套皮肤时一定重犯。
