## 二、任务目标

v0.6.1 发布（`3163f22`）完成后浮出四个问题，前三个是既有缺陷，第四个是用户当轮要求：

1. **发布的事实没人记**。《v0.6.1 · 公共站版式与字号》写于发布之前，明确写着"两条通道本轮均未发布，仍等备案完成"；实际上当日已把静态站与 API 服务器一起上线，回执、进程、验收全是空白。
2. **`npm run check:pages:selftest` 是 20/21**，失败用例把期望值写死成 `expected 149 urls, found 148`。
3. **该自测不在发布门禁内**——这才是问题 2 能存活五个版本的真正原因。
4. 用户要求：把 sitemap 期望值改为**从实际条数派生**、把 `check:pages:selftest` **并入发布门禁**、提交推送、并配置 SSH 公钥。

## 三、问题诊断

| 现象 | 原因 |
| --- | --- |
| 自测报 `sitemap: expected 149 urls, found 148` | 期望值是**写死的字符串**：v0.2.0 时代 148 条种子，当时 149 = 148 页 + 首页。种子在 v0.3.2 涨到 158，检查器（`check-pages.mjs`）跟着算对了，自测里的期望文本没跟。断言的是常量，不是事实 |
| 五个版本无人发现 | `check-pages-selftest.mjs` 自 `71b16ee`（v0.2.0）后没改过，也**从未被任何门禁调用**。`release-gate` 只跑 `check:pages`（检查器本身），没有跑它的反例测试；只有人手动跑时才会红 |
| 推送一直走 HTTPS | 本机 `~/.ssh` 只有 `known_hosts`（建立于今天 13:27 的一次 `ssh -T` 试探），从未生成过密钥，凭据来自凭据管理器里的 token |
| v0.6.1 记录与实际不符 | 文档写在发布动作之前，发布后未回填；属流程缺口，不是记录写错 |
| 门禁耗时口径过期 | `version-release.md` 写着"全套约 40 秒、G6 约 30 秒"，实测已是 134 / 105 秒。这类数字没人校验，会一路错下去 |

## 四、方案与实施

**取舍一：期望值从控制组实测派生，而不是"158 + 1"。**

自测的第一个用例是 `control`——一份空白副本必须全绿。它的 `stats.sitemapUrls` 就是**当时的真实条数**，也是唯一不会说谎的来源。于是把用例的 `expect` 从字符串改成函数：

```js
expect: (ctx) => `sitemap: expected ${ctx.sitemapCount} urls, found ${ctx.sitemapCount - 1}`,
```

**被否决：写 `158 + 1`。** 那只是把同一个错误挪了个位置——下次种子变成 170，它照样烂掉。

配套四处小改：`main()` 里新增 `let sitemapCount = 0`；控制组跑绿时回填 `result.stats.sitemapUrls`；`ctx` 带上该字段；`expect` 的解析统一成 `wanted`（函数则用 `ctx` 求值），失败提示也用 `wanted`。控制组日志顺带打印条数，让"事实"在输出里可见：`pristine copy passes (158 pages, sitemap 159)`。

**取舍二：G2b 紧跟 G2，而不是挂在末尾当 G7。**

- 它需要 G1 刚构出的 `dist/`，越靠近越不会读到上一次产物；
- 它 12.2 秒，比 G6 的 104.7 秒便宜一个数量级，门禁"红灯即停"的原则要求快的放前面；
- 编号不重排（不叫 G7 也不把 G3–G6 后移）：`G3`–`G6` 在历史迭代记录、README、发布作业规则里都有引用，整体后移会让所有旧记录指向错的门禁。用 `G2b` 表达"G2 的自检"，语义最准且零迁移成本。

**变更点**

| 文件 | 变更 |
| --- | --- |
| `scripts/check-pages-selftest.mjs` | `sitemap missing url` 用例期望值改为派生；`ctx` 增加 `sitemapCount`；控制组回填；`expect` 支持函数并统一失败提示。+14 / −7 |
| `scripts/release-gate.mjs` | 新增 `G2b static page checker self-test`（`npm run check:pages:selftest`），置于 G2 之后；注释写明"检查器静默通过比没有检查器更糟"。+10 |
| `README.md` | 命令表标 G2b；门禁表加一行（~12s）；脚本清单与发布流程图同步；补一句"它曾因写死期望条数烂了五个版本" |
| `.qoder/agents/version-release.md` | 门禁表加 G2b；`--skip` 边界与耗时改为实测值（135s / 105s，含分项）；"检查器自检"一节改为"pages 自检已入闸、coverage 自检仍手工"；故障排查表新增 G2b 行 |

**关键实现细节**

- 排查表那一行特意写成"若自测文件里又出现写死的数字，把它改回去而不是改种子"——防止下次有人用迁就夹具的方式"修"红。
- 同类排查：另跑了一遍 `check-coverage-selftest.mjs`，它的断言全部由数据算百分比（`${(rate * 100).toFixed(1)}%`），**没有第二处硬编码数量**，本次不改。

## 十一、总结

这次补的是两处"看不见的破洞"。第一处是自测本身：它断言的不是事实而是常量，所以种子一涨它就悄悄错了五个版本；改成从控制组实测派生之后，它终于跟着数据走。第二处更根本——为什么五个版本没人发现？因为**谁都没跑它**。把它作为 G2b 塞进 G2 之后，用 12 秒换掉一类"检查器自己瞎了还报绿"的失效，这笔账很划算，顺带也修掉了门禁文档里 40 秒/30 秒这种早就过期的数字。另外把 v0.6.1 当时"未发布"的记录补成了实际发布事实（两条通道、进程时间、验收清单、回执缺口），并把推送通道从 token 换成 SSH，同时写清 LocalSystem 读不到用户密钥这条红线。真正欠着的只剩一次人工点发布，和几个需要你拍板的口径问题。
