## 一、为什么先建归因码，而不是先发内容

`/e/<slug>.html` 是给外部引用的静态页，**不含 JavaScript**——文章里贴的链接点进去，前端埋点根本不执行。所以"这篇内容带来了多少访问"只有两个可信来源：

1. `/go/<code>` 的点击行（每次点击写 `partner_clicks`：日、referrer 主机、UA 家族、bot 标记）；
2. 反代日志经 `ingest-access-log` 入库后的域名分类。

第 1 条是主渠道，第 2 条只能粗看平台。**所有对外链接一律走 `/go/`**，这是本文件唯一不可商量的规则。

三条使用约定：

1. **一个码只对应一个落地页。**想让人落到别的条目，就再建一个码，不要复用——复用之后点击数就没法解释。

   注意这个地址返回的是**纯 JSON**（`{"ok": true, "standard": {...}}`），不是网页。收录标准在站内是页首「收录标准」对话框，没有可深链的页面——用 JSON 反而是诚意：规则不在文案里，在接口里。**只把 `panel01` 用在技术向内容**（掘金、方法论段落），别放进面向大众的那条视频。

## 三、链接怎么写

```
https://aihist.net/go/bili01
```

`/go/:path*` 在 `vercel.json` 里被 rewrite 到 `api.aihist.net`，所以**用主域名发就行**，不必暴露 API 域名。页面上的 `canonical`、`og:url` 仍然指向 `aihist.net/e/*.html`，不会出现"引用页在 A、跳转在 B"的分裂。

订阅链接同理带码：`https://aihist.net/api/v1/subscribe?src=bili01`，落库时 `source_path=/subscribe?src=bili01`，`source_channel` 由 referrer 域名判定（小红书、公众号、少数派、即刻四个域名本版已补进 `SOCIAL_REFERRERS`）。

## 四、三个数怎么读

| 数字 | 从哪来 | 读到什么算好 |
|---|---|---|
| `/go/<code>` 点击数 | 合作台账（bot 已剔除，不计入展示值） | 首月每个码 ≥ 30 即内容有效；< 5 说明"链接放了但没人点"，先改放置位置 |
| `source_channel` 分布 | 访问日志分类 | 对应平台从 `other` 迁到 `social`，说明域名补全生效 |
| 订阅带码数 | 订阅者 `source_path` | 首月全渠道合计 ≥ 10 即"值得继续做" |

**不看的数：总 PV。** 北极星是外部引用数（有多少人或站点**在自己的地方**链到 `/e/<slug>.html`），不是自己导了多少流量。

## 六、骨架 B · 掘金技术文

**题目**：五个国产大模型当评审，三票才准入库：一个 AI 编年史的内容管线

**定位**：技术读者关心的是"你怎么防止自己瞎写"。这篇文章的价值不在选题，在**把评审机制与降级路径讲透**——生产常量、失败关闭、缓存失效都在代码里，可以逐条指。

**结构**

1. **问题**：AI 大事记这类内容，最大的风险不是漏，是**编**。一条日期的错，会让整份档案失去被引用的资格。
2. **设计**：规则预筛 → 五席评审 → 硬性排除。给出真实常量（`backend/app/editorial/rules.py`）：
   - `PANEL_SIZE = 5`，DeepSeek / Qwen / GLM / Kimi / MiniMax **各一席**，不是同一个模型的五个副本；
   - `MIN_INCLUDE_VOTES = 3`，裸多数：两席挂掉仍有三票可决，2-2 平票则**暂缓**而不是抢答者胜；
   - `INCLUDE_SCORE = 75`（中位分）；规则命中即硬性排除，不看分数；
   - `RUBRIC_VERSION = "chronicle-v2"`：改门槛必须升版本，否则旧票型会被误当作"按新标准评审过"复用。
3. **为什么是五家厂商**：单一厂商的偏好在 5 票里能直接改写结论；混编后偏好互相抵消。附一段"我们怎么发现的"——v0.3.1 之前是三席两票，扩到五席三票时缓存票型全部作废重评。
4. **失败关闭**：评审超时、返回不可解析、席位缺失时**不入库**，落 `hold`。给一张状态流转图（`pending → hold / included / excluded`）。
5. **可核验的产物**：158 条种子、194 条来源、45 个站点、每条 1–2 个可点开的证据；`/api/v1/standard` 公开规则文本；`/e/<slug>.html` 无 JS 静态页，含 canonical、OG、JSON-LD。
6. **测试与门禁**：后端 273 个测试通过；八道门禁（G0 版本一致性、G1 构建、G2 站点文件、**G2b 检查器自检**、G3 采集管线、G4 收录门槛、G5 覆盖率、G6 后端测试），全套约 134 秒。G2b 用 21 个篡改副本证明检查器真的会红——这一条值得单独写，因为它拦的是"检查器自己瞎了还报绿"。写清"红线是检查真实存在，不是让测试变绿"：本版新增纠错链接时，检查器报 158 处红灯，处置是**给检查器加带 slug 校验的放行**，而不是把链接改绝对地址绕过去。
7. **复盘**：哪一步最容易被跳过（答案：升 `RUBRIC_VERSION`）；下一步要做什么（纠错走 mailto 轻量版，每周纠错超 5 条再换落库队列）。

**必须贴的真实片段**（写作时从仓库取，不要改写数字）

- `rules.py` 里五席/三票/75 分那一段；
- `check-pages.mjs` 里放行 `/api/v1/correct?slug=` 的那三行；
- 一次 `release-gate` 的八道门禁输出（脱敏后贴表格，含 G2b 的 21/21）。

**CTA**

> 规则全文：`https://aihist.net/go/panel01`；档案：`https://aihist.net/go/juejin01`。评审席位与票数都写在页面上，欢迎来挑错。
