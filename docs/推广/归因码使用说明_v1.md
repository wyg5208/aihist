## 一、三十秒版本

**归因码是一个短代号，绑定一个落地页。读者点它，服务器先记一笔账，再把他送过去。**

```
读者在知乎 → 点 https://aihist.net/go/zhihu01
                    ↓
        服务器查台账：zhihu01 有效吗？
                    ↓ 有效
        往 partner_clicks 写一行（哪天、从哪个站来、什么设备、是不是爬虫）
                    ↓
        302 跳到 https://aihist.net/e/transformer-2017.html
```

> **大白话**：想象你在十个不同的工地放材料，每堆材料上贴一张带编号的标签。工人来领料，你只看标签就知道这批料是从哪个工地领走的。归因码就是那张标签，`/go/` 就是那个领料窗口——**所有材料都必须从窗口过一遍，不然你永远不知道谁领的。**

"归因"这个词本身是会计术语：把一笔成本算到具体的项目头上。这里是反过来，**把一次访问算到具体的内容头上**。

## 二、为什么非要绕这一道

### 2.1 引用页没有 JavaScript

站点的 `/e/<slug>.html` 是**不含任何 JavaScript 的静态页**。

这是有意的，不是偷懒：

| 想要的效果 | 为什么必须无 JS |
|---|---|
| 被别人的页面直接引用 | 引用方不用处理脚本加载失败 |
| 被搜索引擎稳定收录 | 纯 HTML 比渲染后的 DOM 更容易被抓取 |
| 被存档站（archive.org 等）完整保存 | 有 JS 的页面存下来是残缺的 |
| 加载快、十几年后还能打开 | 没有依赖就没有腐烂 |

但代价很硬：**前端埋点根本不存在**。你想在页面上放一段统计代码，这条路从第一天就是死的。

### 2.2 于是只剩两个观测点

| 观测点 | 能拿到什么 | 短板 |
|---|---|---|
| 反向代理访问日志 | 访问了哪个 URL、什么时间、UA | referrer 经常是空的，且要等日志落盘再 ingest |
| **`/go/` 跳转** | 明确知道"某个码被点了"，因为跳转由我们自己的代码执行 | 只在"点了链接"时才有数据 |

结论只有一句：**统计能力不来自"控制页面"，来自"控制跳转"。**

所以"所有对外链接一律走 `/go/`"不是洁癖，是这个架构下唯一能测量的方式。裸链一旦发出去，那次访问就在数据里消失了。

> **大白话**：你开了一家店，但店门是敞开的，没有门铃也没有监控（因为装监控会拖慢进出，还会挡住送货的人）。你能数的只有一件事：凡是走正门的人。于是你就把侧门全封了，只留一个正门，门口站个人计数。`/go/` 就是那个唯一正门。

## 三、一次点击的完整路径

以知乎那篇为例，读者点 `https://aihist.net/go/zhihu01`：

| 步骤 | 发生什么 | 在哪 |
|---|---|---|
| 1 | 请求打到 `aihist.net`（Vercel 托管） | — |
| 2 | `vercel.json` 把 `/go/:path*` rewrite 到 `api.aihist.net/go/:path*` | `vercel.json:13` |
| 3 | `find_partner_by_code` 按 code 查 `partners` 表 | `repo_commercial.py` |
| 4 | `partner_is_live` 判断这个码此刻该不该跳 | `repo_commercial.py:350` |
| 5 | 该跳 → `record_click` 写一行流水 → commit | `repo_commercial.py:444` |
| 6 | 302 到目标页，响应头带 `cache-control: no-store, max-age=0` | `redirect.py:31` |

第 4 步不通过，就直接 302 回首页，**不写流水**。

> **大白话**：这就像快递中转站。包裹进站先扫一次码（查到台账），确认这个单号还有效（没撤销、没过期），才在系统里记一笔"已揽收"，然后发往目的地。单号作废的包裹，直接退回发件人那边（回首页），系统里不留记录。

## 四、这张表记了什么

`partner_clicks` 只有 7 列，每一列都有明确用途：

| 列 | 内容 | 为什么是这个 |
|---|---|---|
| `id` | 行主键（UUID） | 每条点击独立可追 |
| `partner_id` | 指向 `partners` 的外键 | 码和账分开存，改码名不影响历史 |
| `day` | 本地日 `YYYY-MM-DD`，按 **UTC+8** 切日 | 报表按天聚合要的就是这个 |
| `at` | 精确时刻 | 排查"凌晨三点一堆点击"这类异常 |
| `referrer_host` | **只有主机名**，如 `zhihu.com` | 完整 referrer 可能带搜索词，属于别人的隐私 |
| `ua_family` | `chrome` / `safari` / `bot` 等 | 区分手机电脑与爬虫 |
| `is_bot` | 布尔 | 见第六节 |

**它不记什么**（这是设计，不是缺失）：

- 不记 IP
- 不记完整 UA 字符串
- 不记 cookie 或任何设备指纹
- 不记访问者的任何身份信息

直接后果：**同一个人点 5 次，就是 5 次点击，不去重。** 一个渠道仪表盘不需要认人，一旦开始认人，它就从"统计"变成了"跟踪"。

> **大白话**：这就像一个景区门口的计数器，人过去它就加一，它不拍照、不记名字、不记住你。所以你今天进出三趟就算三趟。想知道"今天来了多少人"够用，想知道"有几个不同的人"就不够用——那就得装人脸识别，而我们不打算装。

## 五、什么时候不跳、也不记账

判活函数 `partner_is_live`（`repo_commercial.py:350`）要求**四个条件同时满足**：

| # | 条件 | 不满足会怎样 |
|---|---|---|
| 1 | `status == "active"` | `prospect` / `paused` / `ended` 都不跳 |
| 2 | `target_url` 能规范化成完整地址 | 空值或不是 http(s) 就判死 |
| 3 | 今天 ≥ `starts_on` | 起日填了未来日期，当天就是失效的 |
| 4 | 今天 ≤ `ends_on` | 过期即回首页 |

四个状态值的词表是固定的：`prospect`（意向）/ `active`（生效）/ `paused`（暂停）/ `ended`（结束）。

**`kind` 不参与判活**。`sponsor` / `partner` / `mirror` 只影响台账里的分组，写错了也不会导致不跳转。

`normalize_target` 的严格程度值得单说：它要求 scheme 必须是 `http` 或 `https`，且必须有 netloc，否则返回空字符串。注释里写得很直白——**`javascript:` 出现在 `Location:` 响应头里就是 XSS**。

> **大白话**：第 3 条是最容易踩的坑。你把码建好了、状态也是"生效"、目标页也填对了，但起日填的是下周一——那今天点它就是回首页。很多"码建好了却不跳"的排查，最后都落在这一行日期上。

### 两个"看起来像 bug"的地方

`redirect.py` 的文件头注释专门写了这两条，因为它们经常被人当错误来"修掉"：

**① 未知码或过期码，302 回首页，而不是 404。**

- 点到一个失效链接的人是**读者**，不是测试员。给他 404 是把他赶走
- 更要紧的：**404 会告诉扫描器哪些码存在、哪些不存在**。回首页等于什么都不说

**② 跳转响应是 `no-store`，不缓存。**

- 一个被 CDN 或浏览器缓存住的 302，第二次点击**不再经过服务器**，也就不记账了
- 而点击数恰恰是合作方唯一盯着看的那个数。省这一次往返，等于少收一次钱

> **大白话**：第一条像"顾客拿着过期的优惠券来，你笑着说今天活动结束了，请您里面逛"，而不是把券摔回去说"没有这个活动"。第二条像"每张收据必须手写盖章，不许复印"——一复印就不算数了。

## 六、bot：为什么写流水却不算数

写流水时（`record_click`）：

```python
family, _device = classify_ua(user_agent)
is_bot = bool(detect_crawler(user_agent)[0])
```

**爬虫照样写一行，只是 `is_bot=1`。** 而报表读数是这样的（`repo_ops.py:667`）：

```python
.where(PartnerClick.day >= from_day, PartnerClick.is_bot.is_(False))
```

有意做成两层：

| 层 | 规则 | 目的 |
|---|---|---|
| 流水层 | 发生过的事全记，包括爬虫 | 原始记录不可篡改，事后能复盘 |
| 展示层 | 只读 `is_bot=0`，且只取近 30 天 | 口径可解释，不被刷量污染 |

为什么必须这样分？因为**我们自己的验收就是用 bot UA 去点的**。2026-10-27 建那 10 个 csdn 码时，用 `aihist-selftest-bot/1.0` 逐个访问，每个都写了流水。

- 如果 bot 不写行 → 证明不了"码是活的"
- 如果 bot 写行又算数 → 报表第一天就假了

所以现在库里是 **18 行 = 17 行 bot + 1 行真人**（那 1 行真人是 `bili01` 用浏览器点的）。这个构成本身就是可解释的，任何人打开表格都能看懂为什么。

> **大白话**：小区门禁的日志会把外卖员、快递员、抄水表的全都记下来，这是**原始记录**，不能漏。但业委会看的"本月到访人数"报表只算业主和访客，不把快递员算进去。两本账各管各的，谁也别改谁。

**一个容易忽略的细节**：`curl` **不在**爬虫名单里。所以用 `curl` 验一个码，会真实产生一条 `is_bot=0` 的点击。验收时要么接受这个数（并记下来），要么用带 bot 标识的 UA。

## 七、它能回答什么，不能回答什么

很多人以为归因码是个全能统计器。不是。

### 能回答

- 这个码**被点了几次**，精确到天
- 哪个码表现好——也就是**哪篇内容真的把人带来了**
- 访客从哪个站点跳过来（前提是那平台老实传了 referrer）
- 手机还是电脑

### 不能回答

| 问题 | 为什么不行 |
|---|---|
| 有多少人**读到了**文章 | 只有"点链接"才记账，读了不点就是零 |
| 落地页之后做了什么 | 落地页无 JS，到此为止 |
| 是谁点的 | 不记 IP，不认人 |
| 文章被转发了几次 | 别人转发时通常把 `/go/` 换成裸域名 |

最后这条有个直接后果：**覆盖面会随传播衰减**。原文里的码统计得准，转发出去的版本基本统计不到。

所以这个数应该读作"**下限**"，不是总量。真实到达人数 ≥ 报表里的点击数，永远不会少于它。

> **大白话**：这就像你在自家店门口装了个计数器。你能准确知道"从正门进来多少人"，但进来之后逛了几分钟、买没买、出门后跟朋友推荐了没有——计数器一概不知道。它只回答一个问题：**有多少人走进来了。** 对投放决策来说，这一个问题往往就够了。

## 八、一篇一码，以及三条铁律

### 为什么不是"一个平台一个码"

如果知乎所有文章共用一个 `zhihu01`，你只能得到"知乎带来 200 次点击"，然后呢？你没法知道是讲 Transformer 那篇有效，还是讲 1912 那篇有效。

一篇一码，数据才能变成二维的：

| 码 | 对应内容 | 点击 | 怎么读 |
|---|---|---|---|
| `zhihu01` | 十五个转折点 | 180 | 有效，继续 |
| 假设的 `zhihu02` | 另一篇 | 6 | 无效：先改链接位置，别急着改选题 |

### 三条铁律

**铁律一：码发出去了，target 就不能改。**

历史点击已经写进 `partner_clicks` 了。你今天把 `csdn04` 从 `alexnet-2012` 改指到 `gpt-3-2020`，那过去那 50 次点击到底算谁的？**数据当场失去解释力。**

要换落地页 → **新建一个码**（如 `csdn04b`），旧码不动。

**铁律二：一个码只对一个落地页。**

不能"这个码有时候指 A 有时候指 B"。理由同上：复用之后点击数就没法解释了。

**铁律三：过期不删码。**

`ends_on` 到期后码自然失效（302 回首页），但**行要留在表里**。删掉的码会让历史点击失去归属——外键指向一个不存在的行，那批数据就成了孤儿。

所以有效期统一到 2027-06-30，到期前一个月续期，而不是删掉重建。

> **大白话**：这就像存折。你可以新开一个账户，但不能把老账户的名字改成别人的——那样过去每一笔流水都会指错人。老账户可以不再用，但得留着，账才对得上。

| 读数 | 怎么判 |

| 首月每码 **≥ 30** | 这条内容有效 |
| 每码 **< 5** | 不是内容失败，是"链接放了但没人点"→ **先改放置位置**（从文末移到"参考资料"首行） |

**不看的数：总 PV。** 北极星是外部引用数——有多少人或站点**在他们自己的地方**链到 `/e/<slug>.html`，而不是我们自己导了多少流量。

> **大白话**：自己给自己导流量，就像自己在家里办讲座然后自己鼓掌。真正值钱的是**别人愿意在他家门口挂你的海报**。

## 十一、常见误区

**Q：码建好了，为什么不跳转？**
A：按顺序查三处——① `status` 是不是 `active`；② `starts_on` 是不是填了未来日期（最常见）；③ `target_url` 是不是完整的 `https://` 地址（缺 scheme 会被 `normalize_target` 判空）。

**Q：能不能把 `zhihu01` 同时放三篇文章？**
A：技术上能，但你从此不知道是哪一篇带来的点击。要么放弃这个问题的答案，要么一码一篇。

**Q：能不能直接贴 `https://aihist.net/e/transformer-2017.html`？**
A：能打开，但**那次访问在数据里彻底消失**。裸链是"送出东西但不留收据"。

**Q：报表数字比实际少怎么办？**
A：正常，且只能少不能多。原因：① 读了不点不算；② 转发后码丢失；③ 平台不传 referrer 时按码归因仍然准，但看不出是从哪个站来的。

**Q：`curl` 测了一次，报表多了一？**
A：因为 `curl` 不在爬虫名单里，被判成真实点击。这是预期行为，记一笔就行。

**Q：用不同浏览器点两次，算两次还是一个人？**
A：算两次。不去重，也不认人。

**Q：码能重复用吗（比如三个平台都放 `hist01`）？**
A：能，但你只能得到"历史向内容总共被点了 N 次"，无法拆到平台。`hist01` 的定位是**跨平台的主题码**，它衡量的本来就不是平台，是"这个题材有没有人看"。

**Q：过期了，历史数据会没吗？**
A：不会。码失效只是不再跳转，`partner_clicks` 里的历史行永远在。但**删码会让数据失去归属**，所以只续期、不删除。

**Q：为什么不能看"每个码带来多少订阅"？**
A：可以，但要靠订阅侧的 `src` 参数（`/subscribe?src=xxx`），那是另一套参数，不是 `/go/`。两者别混：`/go/` 记点击，`?src=` 记订阅来源。

## 十二、怎么自己验一遍

**验跳转是否正常：**

```
curl -I https://aihist.net/go/bili01
```

看 `Location` 是否为目标页、状态码是否 302。注意：`curl` 会产生一条真实点击。

**验不存在的码：**

```
curl -I https://aihist.net/go/nosuchcode
```

期望 302 回 `/`，且流水行数不变。

**验报表口径：**

进管理台 `https://aihist.net/admin/#/partners`，那里的点击数只统计 `is_bot=0` 且近 30 天。

### 上线前自查（一条待办）

`vercel.json` 里 `/api/:path*` 配了这两行：

```json
{ "key": "CDN-Cache-Control", "value": "no-store" },
{ "key": "x-vercel-enable-rewrite-caching", "value": "0" }
```

**但 `/go/:path*` 没有配同样的头。**

后端已经返回 `cache-control: no-store`，理论上足够阻止缓存。但 `/api` 之所以专门加这条，说明 rewrite 层曾经出现过缓存问题。投放量起来之后，如果 `/go/` 被 Vercel CDN 缓存住，**第二次点击就不记账了**。

自查方法：投放后看一次 `curl -I https://aihist.net/go/<某个真实码>` 的响应里有没有 `x-vercel-cache: HIT`。若有，给 `/go/:path*` 补上面两条 header。

> **大白话**：正面已经写了"此页不缓存"，但快递中转站曾经自作主张抄过一份。多写一张"不要抄"的便条贴在门口，不费事。
