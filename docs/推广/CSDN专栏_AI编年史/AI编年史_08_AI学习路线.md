## 一、总原则：按范式读，不按年份背

先说三条原则，它们决定了后面整张表怎么用。

**原则一：每个方法都是对前一个方法缺陷的回应。**

- 感知机回应的是"手工写规则太贵"；
- 反向传播回应的是"多层没有监督信号"；
- Transformer 回应的是"循环不能并行、长依赖衰减"；
- 推理模型回应的是"一次生成无法自我检查"。

**记不住方法，就记它想修的那个洞。** 洞记住了，方法自然带出来。

**原则二：先跑通最小版本，再读论文。**

读论文最大的挫败感是：看懂每个字，不知道它在解决什么。
先花 30 行代码跑一个玩具版本，再回去读论文，效率差三倍以上。

**原则三：每个阶段都要有一个"能给别人讲"的产出。**

听懂了是假的，能讲清才是真的。所以下面每个阶段都给了过关标准，标准都是"你能不能解释清楚某个问题"。

## 三、阶段 0：前史（1912–1950）

**核心问题**：什么叫"算得出来"？

很多人从 2012 年开始学 AI，结果所有"为什么"都答不上来。前史解决的是定义问题，定义不清，后面全是名词。

**必读（3 篇）**：

1. **图灵 1936《On Computable Numbers》**——不用读完全文，读前三节，抓住"纸带 + 状态表 + 读写头"这个构造。DOI `10.1112/plms/s2-42.1.230`
2. **图灵 1950《Computing Machinery and Intelligence》**——重点是它怎么把"机器能否思考"替换成"模仿游戏"。DOI `10.1093/mind/LIX.236.433`
3. **香农 1938《A Symbolic Analysis of Relay and Switching Circuits》**——逻辑怎么落到电路上。这篇决定了"符号"能变成"器件"。

**手练**：用 10 行代码写一个"停机检测器"，然后让它检测自己。

```python
def halts(program, input_):
    """如果能判断 program(input_) 会不会停，就返回 True。"""
    # 你写不出来。这不是你的问题——这是图灵证明过的。
    raise NotImplementedError

def paradox():
    if halts(paradox, None):
        while True:      # 如果检测器说我会停，我就死循环
            pass
    return               # 如果检测器说我不停，我就停
```

**过关标准**：能向别人解释——为什么 `halts` 不可能存在，以及这和"AI 有没有极限"是两件不同的事。

## 四、阶段 1：符号主义（1956–1987）

**核心问题**：能不能把人类知识写进机器？

**必读（4 篇）**：

1. **达特茅斯提案（1955/1956）**——看它当年的乐观预期，再看后面落空的部分。这是"承诺—落空"循环的第一份原始材料。
2. **Dendral（1965）**——第一个专家系统，"知识库 + 推理机"的架构从这里开始。
3. **MYCIN（1974）**——数百条规则诊断血液感染，评估中达到专家水平。
4. **XCON / R1（1980）**——DEC 用它配置 VAX 订单，专家系统第一次证明能算出钱。

**手练**：写一个 50 条的规则引擎（诊断"电脑开不了机"就够）。

```python
RULES = [
    ("电源灯不亮", "检查电源线", "power"),
    ("电源灯亮但无显示", "检查显示器连接", "display"),
    # ... 凑到 50 条
]

def infer(facts: set[str], rules):
    fired = []
    changed = True
    while changed:                 # 前向链：能推就推，推到不动为止
        changed = False
        for cond, action, tag in rules:
            if cond in facts and tag not in facts:
                facts.add(tag)
                fired.append((cond, action))
                changed = True
    return fired
```

**过关标准**：能说出专家系统的三个死因——

1. **知识获取瓶颈**：规则要人写，写一条规则的边际成本很高；
2. **脆弱性**：规则之外的情况完全不会处理（SHRDLU 在积木世界里很强，出了积木世界就废）；
3. **不可扩展**：规则之间会冲突，规则库一大就自相矛盾。

**顺带一个教训**：1982 年日本第五代计算机计划押注逻辑推理，十年后收缩。它失败的不是"逻辑不行"，是"把宝押在单一范式上"。

## 五、阶段 2：连接主义（1943–1998）

**核心问题**：能不能不写规则，让机器从数据里学？

**必读（5 篇）**：

1. **McCulloch-Pitts 1943**——神经元作为带阈值的逻辑单元。
2. **Hebb 1949《行为的组织》**——"同时激活，连接增强"。学习第一次有了机制假设。
3. **Rosenblatt 1958《The Perceptron》**——可学习权重 + 硬件实现。
4. **Minsky & Papert 1969《Perceptrons》**——只读它的结论部分：单层无法表示非线性函数。
5. **Rumelhart, Hinton, Williams 1986《Learning representations by back-propagating errors》**——把误差反传讲清楚。这篇是整条线的心脏。

**手练**：用 numpy 手写一个单层感知机，训练 XOR，然后观察它**一定失败**。

```python
import numpy as np

X = np.array([[0, 0], [0, 1], [1, 0], [1, 1]], dtype=float)
y = np.array([0, 1, 1, 0], dtype=float)          # XOR
w, b, lr = np.zeros(2), 0.0, 0.1

for epoch in range(2000):
    pred = (X @ w + b > 0).astype(float)
    err = y - pred
    w += lr * (X.T @ err) / len(X)
    b += lr * err.mean()

print("最终预测:", (X @ w + b > 0).astype(int))   # 永远有两个错
```

跑完你会看到：无论训练多少轮，它最多只能分对三个。**这就是 1969 年那本书的内容，你亲手复现了一次。**

然后加一个隐藏层，再跑一次——它就能全对。**这也就是为什么"多层"和"可训练"必须同时成立。**

**过关标准**：能解释三件事——为什么单层做不到 XOR；为什么多层能做到但 1969 年训不了；1986 年的反向传播具体补了哪一环。

## 六、阶段 3：深度学习（2006–2017）

**核心问题**：条件什么时候齐了？

**必读（5 篇）**：

1. **Hinton & Salakhutdinov 2006（Science）**——逐层预训练，让"深"重新可行。
2. **ImageNet 2009**——数据变成公共基础设施。
3. **AlexNet 2012**——GPU + ReLU + Dropout，误差率断崖。
4. **ResNet 2015**——残差连接，百层可训。
5. **Transformer 2017**——自注意力取代循环。

**手练**：手写多头自注意力（第 05 篇给了完整代码），必须包含**因果掩码自检**。

**过关标准**：能回答三个问题——

1. O(T²) 是从哪来的？（`QKᵀ` 生成 T×T 的分数矩阵）
2. 为什么要除以 √d_k？（点积方差随维度增长，softmax 会饱和）
3. 为什么 Transformer 能并行而 RNN 不能？（RNN 第 t 步依赖第 t-1 步）

## 七、阶段 4：大模型（2018–2026）

**核心问题**：规模之后，还剩下什么可做的？

**必读（5 篇）**：

1. **GPT-1 2018**——"生成式预训练 + 微调"的范式。
2. **GPT-3 2020**——少样本上下文学习，提示词登场。
3. **Chinchilla 2022**——参数与数据要同比例扩展，纠正"越大越好"。
4. **InstructGPT 2022**——RLHF 让模型更好遵循指令，是 ChatGPT 的前身。
5. **DeepSeek-R1 2025**——强化学习激发长链推理 + 开放权重。

**手练**：做一个最小的 RAG，**必须带引用**。

```python
# 最小 RAG 骨架（伪代码，重点是"必须带引用"这一条）
def answer(question: str) -> dict:
    hits = search(question, top_k=5)              # 1. 检索
    context = "\n".join(f"[{i+1}] {h.text}" for i, h in enumerate(hits))
    prompt = f"只根据下面的材料回答，每个结论后面标注来源编号。\n\n{context}\n\n问题：{question}"
    text = llm(prompt)                            # 2. 生成
    used = {int(n) for n in re.findall(r"\[(\d+)\]", text)}
    if not used:
        return {"ok": False, "reason": "没有引用，视为未回答"}   # 3. 无引用 = 失败
    return {"ok": True, "text": text, "sources": [hits[i - 1].url for i in used]}
```

**过关标准**：你的 RAG 在"材料里没有答案"时，应该回答"材料里没有"，而不是编一个。

**这一条比准确率更重要。** 会编的 RAG 在生产环境里是负资产。

### 7.1 三个自己就能算的验收指标

说过关要过"不编"这一关，得给出算式，否则只能自说自话。下面三个指标不需要标注平台，自己就能算：

**一、拒答率**

先造一份"无答案集"：20 道题，每题都先确认检索回来的前 5 条里没有任何一句能回答问题。然后统计：

```
拒答率 = 回答"材料里没有"的题数 / 20
```

这个数应该在 0.8 以上。低于 0.6，说明你的提示词在暗示模型"必须给个答案"——这是最常见的设计错误。

**二、引用可追溯率**

先正则取出回答里所有 `[n]`，再做两道检查：

1. 编号是否落在检索材料的范围内（`1 <= n <= k`）；
2. 被引材料里能否真的找到支撑这句话的段落。

```
引用可追溯率 = 通过两道检查的引用数 / 全部引用数
```

只有第一道检查（编号合法）而没做第二道，很容易出现"编号对、内容不对"——模型把 `[3]` 贴在一句材料里根本没有的话后面。这种错误比不引用更危险，因为它看上去可信。

**三、忠实度（faithfulness）**

每个断言是否被所引材料支持。这一项不需要自动化：人工抽 20 条回答就够。

三个指标都有一个读法上的要求：**看最差的那 10 题，不看平均值。** 平均 95% 而最差 10 题全错，说明你的系统在某些问题类型上是系统性失败，平均值把这个藏住了。

### 8.2 资料怎么取舍：五类东西，五种用法

上一节排的是时间，这一节排的是资料。学 AI 最大的浪费不是学得慢，是**用错的方式读对的东西**。

| 资料类型 | 该怎么用 | 别怎么用 |
|---|---|---|
| 原文论文 | 抓摘要、图、结论三段，再回头啃方法 | 从第一页读到最后一页 |
| 综述（survey） | 先用来建地图，再按图索骥 | 把综述里的转述当原始结论引用 |
| 官方文档 / 技术报告 | 查接口、参数、版本变更 | 用它替代论文里的方法说明 |
| 开源代码 | 跑通最小示例，改一个参数看输出怎么变 | 把"能跑"当成"懂了" |
| 二手博客 / 视频 | 卡住时换一种讲法 | 作为事实来源 |

最后一行是这份清单里唯一不能灵活处理的：**二手资料的定位是"帮我读懂一手"，不是"替代一手"。**

所以读完一篇博客觉得自己懂了，还要回原始材料确认一次。否则你带走的不是知识，是别人对知识的翻译——而翻译会丢条件，条件就是第 03 篇讲的那件事。

给自己加一条硬规矩：任何你打算写进简历或讲给别人的结论，必须能指向上表前两类资料；指不到的，标成"待核"，别当作已知。这个习惯比多学两个框架值钱。

## 九、五条最常见的弯路

**弯路一：从"大模型应用"入门，跳过基础。**

直接学 RAG 框架、Agent 框架，能做出 demo，但一旦效果不对就无从下手。因为不知道注意力怎么算，就不知道"为什么长上下文会退化"。

**弯路二：把论文当小说读。**

从头读到尾，读完记不住。正确做法：先读摘要 + 图 + 结论，跑一遍代码，再回去读方法。

**弯路三：只学最新，不看历史。**

只学 2024 年之后的模型，会重复踩已经被踩过的坑。比如"参数量越大越好"——Chinchilla（2022）已经修正过，但每年仍有人重新提。

**弯路四：用准确率做唯一验收。**

在生成任务上，准确率会骗人：模型编造一个看起来合理的答案，评分器可能给高分。**拒答率、引用可追溯率，比准确率更能反映系统是否可用。**

**弯路五：不记录证据。**

学完就忘，是因为没有留下"我当时的判断依据"。建议从今天开始，给自己建一个小档案：每读一篇论文，记三行——解决了什么洞、关键数字、什么情况下不适用。

## 十、总结

**三个关键点**：

1. **按范式读**：每个方法都是对前一个方法缺陷的回应。记住洞，方法自然带出来。
2. **先跑最小版本，再读论文**：30 行代码能省三小时阅读。
3. **验收标准要可自判**：能不能讲清某个问题、能不能在材料无答案时拒答——这些比"学完了"有意义。

**一个公式**：

```
掌握 = 能复现（代码） × 能解释（为什么） × 能判断（什么时候不适用）
```

三项都成立才算学会。只有第一项，是会用工具；只有前两项，是会考试；三项齐了，才是工程师。

**思考题**：

1. 五个阶段里，你最想跳过哪一个？跳过它，后面哪一章你会听不懂？
2. 如果只能用 100 行代码证明"你懂 Transformer"，你会写哪 100 行？
