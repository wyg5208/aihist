## 一、先说结论

自注意力替换掉的是**循环**，它换来的有两条，而且两条都指向规模化：

1. **并行度**：RNN 必须按时间步串行计算，第 t 步依赖第 t-1 步；自注意力把整个序列一次性做矩阵乘，训练可以完全并行。
2. **路径长度**：RNN 里第 1 个词到第 1000 个词要走 999 步；自注意力里它们只隔一层。信息传递距离从 O(T) 降到 O(1)。

一句话：**RNN 的问题是"训不快、记不远"，自注意力同时解决了这两个问题，代价是 O(T²) 的计算量。**

而这个代价，恰好可以被 GPU 的并行能力和后来的工程优化吸收——所以它赢了。

## 二、问题：循环结构的两个硬伤

在 2017 年之前，序列建模的主流是 RNN 与 LSTM。LSTM（1997）用门控机制缓解了梯度消失，成为近二十年的主力结构。但它有两个绕不过去的问题。

**硬伤一：串行**

```
h1 = f(x1, h0)
h2 = f(x2, h1)
h3 = f(x3, h2)
...
hT = f(xT, hT-1)
```

第 t 步必须等第 t-1 步算完。这意味着**一个长度为 T 的序列，训练时至少要 T 个串行步骤**。GPU 有几千个核，但在这里只能用上一小部分——因为没东西可并行。

**硬伤二：长依赖衰减**

信息从第 1 个位置传到第 T 个位置，要经过 T-1 次变换。即使有门控，梯度在长链路上仍然会衰减或爆炸。LSTM 缓解了这个问题，但没有消除它。

这两条合起来，就是"RNN 训不快、也记不远"。

## 三、自注意力怎么工作

### 3.1 一句话版本

每个位置都生成三个向量——Query（我要找什么）、Key（我提供什么）、Value（我实际带的信息）；
然后用我的 Query 去和所有位置的 Key 做点积，得到一组权重，再用这组权重加权求和所有位置的 Value。

用生活化的比喻：**这是一次"全场广播 + 各自选择"**。每个人喊出自己能提供什么（Key），
每个人也问出自己想要什么（Query），匹配度高的就多听一点，最后按匹配度把听到的内容加权汇总（Value）。

### 3.2 公式

```
Attention(Q, K, V) = softmax(QKᵀ / √d_k) · V
```

三个细节值得说清：

- **为什么除以 √d_k**：点积的方差随维度线性增长，维度大时 softmax 会饱和成 one-hot，梯度消失。除以 √d_k 是把方差拉回 1。
- **为什么多头**：单头只能学一种"关注模式"。多头把 d_model 切成 h 份，每份独立做注意力，等于让模型同时学 h 种不同的关联（语法、指代、位置……）。
- **为什么加残差与 LayerNorm**：和 ResNet（2015）同一个理由——让梯度有直通路。

### 3.3 位置从哪来：位置编码

自注意力本身不知道顺序，所以位置必须被"编码进去"。最常见的两种做法：

**做法一：正弦位置编码**（原论文用法）

```
PE(pos, 2i)   = sin(pos / 10000^(2i/d))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d))
```

用不同频率的正弦、余弦函数组合，每个位置得到一个唯一的向量。它的好处是：任意两个位置的编码之间存在只依赖"距离"的线性关系，模型可以据此外推。

**做法二：RoPE（旋转位置编码）**

不把位置加到词向量上，而是把位置信息编进 Q、K 的旋转角。这样两两做点积时，结果只依赖相对距离，而不是绝对位置。这是目前长上下文模型的主流选择。

两者的差别不在"有没有位置"，而在**位置是"加进去的"还是"转进去的"**。后者在长度外推上更自然，也更符合"我们真正关心的是相对关系"这个直觉。

### 3.4 代码骨架

以下是最小可运行的实现（PyTorch，含因果掩码），可以直接跑：

```python
import math
import torch
import torch.nn as nn
import torch.nn.functional as F


class SelfAttention(nn.Module):
    """多头自注意力。causal=True 时用于 decoder-only 语言模型。"""

    def __init__(self, d_model: int, n_heads: int, dropout: float = 0.0):
        super().__init__()
        assert d_model % n_heads == 0, "d_model 必须能被 n_heads 整除"
        self.n_heads = n_heads
        self.d_head = d_model // n_heads
        # 一次投影出 Q、K、V，比三个 Linear 少一次 kernel launch
        self.qkv = nn.Linear(d_model, 3 * d_model, bias=False)
        self.out = nn.Linear(d_model, d_model, bias=False)
        self.drop = nn.Dropout(dropout)

    def forward(self, x: torch.Tensor, causal: bool = True) -> torch.Tensor:
        B, T, C = x.shape
        q, k, v = self.qkv(x).chunk(3, dim=-1)          # 各 (B, T, C)

        # (B, T, C) -> (B, H, T, Dh)
        q, k, v = [
            t.view(B, T, self.n_heads, self.d_head).transpose(1, 2)
            for t in (q, k, v)
        ]

        scores = q @ k.transpose(-2, -1) / math.sqrt(self.d_head)   # (B, H, T, T)

        if causal:
            # 上三角为 True，屏蔽掉"看未来"
            mask = torch.ones(T, T, dtype=torch.bool, device=x.device).triu(1)
            scores = scores.masked_fill(mask, float("-inf"))

        attn = F.softmax(scores, dim=-1)
        attn = self.drop(attn)

        y = attn @ v                                     # (B, H, T, Dh)
        y = y.transpose(1, 2).contiguous().view(B, T, C)
        return self.out(y)


class Block(nn.Module):
    """Transformer block：pre-LN + 残差 + FFN。"""

    def __init__(self, d_model: int, n_heads: int, mlp_ratio: int = 4, dropout: float = 0.0):
        super().__init__()
        self.ln1 = nn.LayerNorm(d_model)
        self.attn = SelfAttention(d_model, n_heads, dropout)
        self.ln2 = nn.LayerNorm(d_model)
        self.mlp = nn.Sequential(
            nn.Linear(d_model, mlp_ratio * d_model),
            nn.GELU(),
            nn.Linear(mlp_ratio * d_model, d_model),
            nn.Dropout(dropout),
        )

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        x = x + self.attn(self.ln1(x))     # 先 norm 再进子层（pre-LN 更稳）
        x = x + self.mlp(self.ln2(x))
        return x


if __name__ == "__main__":
    torch.manual_seed(0)
    x = torch.randn(2, 8, 64)              # batch=2, seq=8, d_model=64
    block = Block(d_model=64, n_heads=4)
    y = block(x)
    print(y.shape)                          # torch.Size([2, 8, 64])

    # 因果性自检：改动最后一个 token，前面位置的输出不应变化
    x2 = x.clone()
    x2[:, -1, :] += 1.0
    y2 = block(x2)
    print("前缀一致:", torch.allclose(y[:, :-1], y2[:, :-1], atol=1e-5))
```

最后那个自检很值得留：**因果掩码写错是新手最常见的 bug**，它不会报错，只会让模型"偷看答案"——训练 loss 好看，推理崩。

### 3.5 复杂度对比

| 结构 | 每层计算量 | 最长路径 | 能否并行训练 |
|---|---|---|---|
| RNN / LSTM | O(T · d²) | O(T) | 否（按时间步串行） |
| 自注意力 | O(T² · d) | O(1) | 是（整段矩阵乘） |
| 卷积（固定核） | O(k · T · d²) | O(T / k) | 是 |

这张表解释了一切：

- T 小的时候（比如 512），O(T²·d) 远小于 O(T·d²)，注意力更便宜；
- T 很大时（比如 100 万），O(T²·d) 爆炸，这就是为什么后来出现各种稀疏注意力、线性注意力、以及长上下文优化（2026 年 GLM-5.2 用 IndexShare 等机制降低长上下文注意力开销，就是这一类工作）。

**算一笔具体的账**：T=512、d=768，注意力分数矩阵是 512×512。看起来很小，但要乘以头数——8 头就是 8 张 512×512 的矩阵，逐层累加。T 翻到 8192，每张矩阵大 256 倍，显存立刻吃紧。

这也是为什么"长上下文"从来不只是"把 T 改大"：**它要同时解决算力、显存、以及位置外推三件事。**

## 四、从 Transformer 到 GPT：三次关键选择

Transformer 只是一个结构。真正把它变成大模型的是三次选择，每次都在放弃一些东西。

### 4.1 第一次选择：只用 decoder

原始 Transformer 是编码器—解码器结构，为翻译设计：编码器读源语言，解码器生成目标语言。

GPT 路线只保留 decoder，任务是**预测下一个 token**：

```
输入：今天 天气 真
目标：    天气 真 好
```

这个选择的代价：失去了"双向看完整句子"的能力（BERT 走的是另一条路）。
收益：一个目标函数就够用，且天然支持生成。

把三条路线摆在一起看，取舍就很清楚：

| 结构 | 代表 | 看的方向 | 擅长 | 不擅长 |
|---|---|---|---|---|
| encoder–decoder | 原版 Transformer、T5 | 编码看全句，解码看左半 | 翻译、摘要这类"输入到输出"的转换 | 单向开放式生成不是它的主场 |
| encoder-only | BERT | 双向看全句 | 分类、抽取、相似度 | 不能直接生成 |
| decoder-only | GPT 系列 | 只看左边 | 生成、上下文学习、统一成一个目标函数 | 对"全局结构"的建模靠层数堆 |

2026 年回看，decoder-only 赢的原因不是它在单项上最强，而是**它只需要一个目标函数**。
一个目标函数意味着：所有任务都能改写成"给定前文，预测下一个 token"，于是数据、训练、推理三套工程只需要做一遍。
工程上的统一，最后压过了结构上的精致。

### 4.2 第二次选择：预训练 + 微调

2018 年 GPT-1 验证了"生成式预训练 + 下游微调"——先用海量无标注文本预训练，再在具体任务上微调。

这个范式的价值是：**标注成本被摊薄了**。一个预训练模型可以服务几十个下游任务。

### 4.3 第三次选择：规模本身就是方法

2020 年 GPT-3 发布，1750 亿参数，展示少样本上下文学习。

这次选择最激进：**不微调，只在提示里给几个例子**。

```
把下面的中文翻译成英文：
苹果 -> apple
香蕉 -> banana
西瓜 -> 
```

模型没有为这个任务训练过，但它在上下文里"学会"了任务形式。这一步之后，"提示词"成为与大模型交互的主要方式，也把产品形态从"API + 微调"改成了"对话框"。

补一条后来的修正：2022 年 Chinchilla 缩放定律指出，在固定算力下参数量与训练数据量应同比例扩展，纠正了此前"越大越好"的参数扩张倾向。它是这条路线的一次自我校准——**规模有效，但要按配比来**。

## 五、三条常见误解

**误解一：注意力机制是 Transformer 发明的**

不是。在 seq2seq（2014）里，注意力已经被用来解决"编码器把整句压成一个向量"的瓶颈——解码时动态地看编码器的不同位置。Transformer 的贡献是**把注意力变成唯一的结构**，去掉了循环。

**误解二：注意力权重高就代表那个词重要**

不完全。注意力权重是**信息路由的概率分布**，它表示"这一层、这个头、这个位置拿了多少信息"，不等于"这个输入对最终输出贡献大"。多头之间存在冗余，后面的层还会重新组合，而且 LayerNorm 与残差会把信号混合。要把注意力当解释，至少需要跨层、跨头、跨样本的统计，单看一张热力图不够。

**误解三：模型天然理解顺序**

不是。自注意力对输入是**置换等变**的——打乱顺序，输出跟着打乱，模型本身察觉不到"谁在前"。所以必须显式注入位置信息（位置编码、RoPE 等）。这也解释了一个常见困惑：为什么位置编码方式会影响长上下文表现。

## 六、工程清单

如果要自己训或微调，这五条最容易踩：

1. **位置编码要跟长度匹配**。训练长度 2K、推理长度 32K，位置编码不扩展就会崩。
2. **pre-LN 比 post-LN 稳**。post-LN 在深层时梯度容易爆，需要 warmup；pre-LN 对 warmup 不敏感。
3. **KV Cache 是推理的必需品**。自回归生成时，历史 token 的 K、V 不会变，缓存起来可把每步复杂度从 O(T²) 降到 O(T)。
4. **因果掩码要写自检**。就是第 3.4 节最后那段断言，五秒钟能省两天。
5. **数值稳定性**：softmax 前减最大值、混合精度要注意 LayerNorm 用 fp32——这些都是训崩过才会记住的细节。

### 6.1 KV Cache 到底省了什么，又贵在哪

先说它省什么。自回归生成是逐个 token 出的：第 t 步需要前 t 个 token 的 K、V。而这些 K、V 在之前每一步已经算过了，**不缓存就得重算**。

| 做法 | 第 t 步的计算量 | 说明 |
|---|---|---|
| 不缓存 | 重算前 t 个位置 | 每步 O(t²·d)，总 O(T³) |
| 缓存 | 只算新 token 的 K、V | 每步 O(t·d)，总 O(T²) |

再说它贵在哪。缓存要把每层、每个 token 的 K 和 V 都存在显存里：

```
显存 = 2（K 和 V） × T × d_model × 层数 × 字节数
```

代入一组真实量级的数：T = 8192、d_model = 4096、32 层、fp16（2 字节）：

```
2 × 8192 × 4096 × 32 × 2 ≈ 4.3 GB
```

**4 GB 只为一个请求的上下文。** 并发十个就是 43 GB。这就是"长上下文很贵"的直接原因——不是算不动，是存不下。

### 6.2 顺手算一下注意力有多少参数

一个不带 bias 的多头注意力，参数来自两处：

```
qkv 投影：d × 3d = 3d²
输出投影：d × d   = d²
合计：4d²
```

d = 4096 时，单层约 6700 万参数；32 层光注意力就约 21 亿。再加上 FFN（通常 4d² 量级），就能理解为什么千亿参数模型里大部分参数在 FFN 而不在注意力。

这个账算一遍，你对"参数量"的直觉会准很多。

### 6.3 训练不稳定的三种表现，以及各自的判断信号

这一节不是理论，是排查手册。训大模型时最先崩的往往不是架构，是数值。

| 表现 | 典型信号 | 常见原因 | 先改哪个 |
|---|---|---|---|
| loss 突然尖峰后又回落 | 第 N 步 loss 从 2.x 跳到 8.x，几十步内恢复 | 个别 batch 梯度过大 | 梯度裁剪（按范数裁到 1.0） |
| loss 直接变成 NaN | 一旦出现就再也不恢复 | fp16 上溢（softmax 前没减最大值、LayerNorm 用 fp16） | 混合精度里把 softmax、LayerNorm 强制 fp32 |
| 前期正常，深层不收敛 | 浅层梯度正常，靠输出端几层几乎不更新 | post-LN 深层梯度爆炸 | 换 pre-LN，并保留 warmup |

三条经验，都是从"训崩过"换来的：

1. **先看是不是数值问题，再怀疑架构**。九成的"模型不收敛"最后落在精度、初始化或学习率上，而不是结构写错。
2. **梯度裁剪不是可选项**。它的作用不是优化，是给单步更新装一个上限，防止一个坏 batch 把权重推到不可恢复的区域。
3. **warmup 要配 pre-LN 一起看**。post-LN 必须靠 warmup 压住早期梯度；换成 pre-LN 后对 warmup 不敏感，但直接去掉 warmup 仍可能在最初几百步发散。

补一句诚实的边界：上面的信号只对"从零训练"成立。微调一个已经收敛的基座模型时，loss 曲线通常很平，这时候要看的是下游指标，不是 loss。

## 七、总结

**三个关键点**：

1. **自注意力换掉的是循环，换来的是并行度与短路径**。代价是 O(T²)，而这个代价被 GPU 与工程优化吸收了。
2. **Transformer 只是结构，GPT 是选择**。decoder-only、生成式预训练、规模与上下文学习，这三次选择决定了今天的形态。
3. **三条误解都源自把"机制"当"解释"**。注意力是路由，不是原因；位置编码是假设，不是自明。

**一个公式**：

```
大模型可行 = 并行训练（吞吐） × 短路径（长依赖） × 规模（容量） ÷ O(T²)（成本）
```
